Editors

.jsc has a language server, joust-lsp. It ships in the @julclang/joust npm package and analyses each file with the same front end the build uses, so its errors are the build’s (ADR-0021). What each editor gets:

VS Code Neovim, Helix, other LSP clients
Diagnostics as you type, with stable JSC codes ✓ ✓
Hover, go to definition, references (across files and into java: libraries), symbols, folding, selection ranges, semantic tokens ✓ ✓
Completion, quick fixes, rename, Format Document ✓ —
The build on save (in memory: the processor’s and JuLC’s errors, the ABI comparison, the joust.lock check) ✓, in a trusted project —
joust fmt from the command line ✓ ✓

The editing features are VS Code’s only. The server offers an edit only to a client known to reject one when the text changed after the answer was computed (ADR-0021 D4a), and the extension is that client. Other editors get the read-only features. There, format with joust fmt <file> from the shell, or from an editor hook that runs it on save.

The server never writes into your project. It runs advisory, with its own bundled compiler, unless the project’s own compiler matches it.

VS Code

Section titled “VS Code”

Install the JOUST extension, julc.vscode-joust. It has its own version, apart from JOUST’s: each version bundles the compiler of one JOUST release, and each JOUST release that publishes the extension bumps its patch. Its changelog names the JOUST release each version bundles. It is published as a pre-release while JOUST is one, so pick one of these:

  • From the Visual Studio Marketplace. In the Extensions view, search for julc.vscode-joust and install it (choose the pre-release version if VS Code offers both). Or from a terminal:

  • From a JOUST release on GitHub. Releases that include the extension list vscode-joust-<ext>.vsix among their assets (the release notes alone are no sign: look at the asset list). Optionally check that the release’s own workflow built it from the release’s tag (this needs the GitHub CLI), then install it:

    If a maintainer attached the release’s assets by hand, the check passes with --source-ref refs/heads/main instead. If neither passes, don’t install the file.

    VSCodium and other editors that use Open VSX can install the .vsix the same way.

The extension bundles the server and its compiler, and it honours Workspace Trust:

  • In Restricted Mode, it analyses with the bundled compiler and runs nothing from the workspace.
  • In a trusted folder, it may use the project’s own compiler: only that compiler’s two engine files, after checking them.

Rename goes through JOUST: Rename Symbol. It renames locals, parameters, fns, types, enums, variants, fields, state fields, actions, destroys, views, events and owned types. Renaming an owned type also renames its methods’ and invariants’ qualifiers and its admits. A field renamed in an owned type is renamed where the object is read: in its methods’ bodies and modifiers, and in keyed by for a keyed type’s key. A params field is also renamed in init migrate from params.f. Owned methods, the purposes’ handlers and init migrate cannot be renamed: the rename refuses them. JOUST: Show generated Java opens the lowered class, and Accept ABI… reviews a changed ABI manifest before accepting it. Format Document, and format on save if you turn it on, use the same formatter as joust fmt. The formatting style belongs to the compiler’s version (version 1 today). When the extension analyses with its bundled compiler (advisory), it formats with that one too, so a project pinned to another JOUST version may format differently in CI.

How the extension is published

Each JOUST release builds the .vsix from its tag, with the compiler engine of the @julclang/joust package that npm serves for that version, and attaches it to the GitHub release with its SHA-256 and a provenance attestation. The Marketplace listing is that same file, published unchanged after a maintainer approves. An Open VSX listing is not there yet.

Other editors: a server you installed

Section titled “Other editors: a server you installed”

Editors other than VS Code have no workspace trust, so JOUST’s configurations start a joust-lsp you installed yourself, by absolute path. A repository you open never chooses the program that runs. Install a pinned version globally and note the path:

npx joust is never used for an editor: it would run whatever version a project or the registry resolves.

Neovim (0.11 or later)

Section titled “Neovim (0.11 or later)”

Put JOUST’s module, editors/neovim/lua/joust.lua, on your runtimepath (for example in ~/.config/nvim/lua/), then in your init.lua:

The module checks the path, sets the jsc filetype and configures the server through vim.lsp.config. It refuses:

  • a bare name or a relative path;
  • npx;
  • a project’s node_modules/.bin;
  • a server, or node, inside the project of the buffer you open. The project is the one JOUST’s markers find: joust.config.json, package.json or settings.gradle, never your home directory itself. An install under your home directory (nvm, volta, asdf, an npm prefix of ~/.npm-global) is your own, wherever Neovim is started.

The server runs on an absolute node. By default that is the first node on an absolute PATH entry; a relative entry such as ./node_modules/.bin is never used, since it would let a project choose the interpreter. On Windows, give node explicitly; the module does not search PATH there. Elsewhere you can give it too:

With the tree-sitter package installed (below), it also starts tree-sitter highlighting and folding for .jsc buffers.

Any other LSP client

Section titled “Any other LSP client”

Start /absolute/path/to/node /absolute/path/to/joust-lsp --stdio for files ending in .jsc. Use the project root, the directory holding joust.config.json or package.json, as its workspace folder.

The tree-sitter grammar

Section titled “The tree-sitter grammar”

Highlighting and folding in Neovim and Helix come from tree-sitter-jsc. Releases that include it list tree-sitter-jsc-<version>.tar.gz among their assets, with its SHA-256 in the release’s editor-assets-<joust-version>-SHA256SUMS.txt and a provenance attestation. Download it, optionally check it, and unpack it where you keep editor plugins:

As for the .vsix, assets a maintainer attached by hand pass with --source-ref refs/heads/main instead. That directory is the /ABSOLUTE/PATH/TO/tree-sitter-jsc the Helix configuration above names. The archive holds:

  • the grammar and the generated parser (src/);
  • the queries (queries/, and neovim/queries/jsc/);
  • Helix’s highlights, with Helix’s capture names (helix/queries/jsc/);
  • EDITORS.md, the steps above in short.

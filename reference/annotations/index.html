Annotations

This page lists every annotation in julc-state-api (package org.julclang.state.api), grouped by what it is for. For each one you get its target, its elements with their types and defaults, the method shape the processor accepts, what the generated validator checks on chain, and a line from a real example. The source of each annotation is in julc-state-api/src/main/java/org/julclang/state/api/; the rules quoted below come from the processor’s ContractReader, which reports each one as a compile error.

All annotations have CLASS retention: they exist for the annotation processor and are not read at run time.

Note

Events are not an annotation. A method emits them by returning a result record with an events component (see Result records). Several names in the annotation catalogue (@State, @Param, @Event, @Upgradeable, @Calls, @Storage, @Anonymous, @MultiSig) are proposals that did not ship under those names; they are not in julc-state-api. The @Param you may see on a plain JuLC validator (such as examples/treasury/.../Guardian.java) is JuLC’s own annotation, not JOUST’s.

Method kinds and parameter order

Section titled “Method kinds and parameter order”

Every contract method carries exactly one kind annotation: @Init, @Action, @Destroy, @View, @OwnedInit, @OwnedAction, @OwnedDestroy, @Migrate, @Invariant or one purpose handler (@Withdraw, @Certify, @Votes, @Propose). Policy annotations (@Payable, @SignedBy, @OnlyOwner, @ValidAfter, @ValidBefore, @Batched, @Quorum, @AuthorizedBy, @Admits, @Receives) need a kind annotation on the same method.

The processor enforces these rules on every kind:

  • Contract methods are public static, not generic, and have unique names (no overloading).
  • A method name cannot be a member of the generated client: deploy, at, contract, state, instance, instanceId, lovelace, fullValue, SPEC, params, policyIdFor, checkedState, checkedObject (and, for @Batched contracts, INTENTS, batch, pendingIntents, intent).
  • Parameter names callerAccount, payLovelace, payAssets, runtime, params, authorization, cosigners, ctx and maps are reserved; @Init also reserves seed and instance.
  • A MerkleMap or MapEntry can only be a component of the state (or owned) record, never an argument.

Parameters come in this order (each part optional unless the kind requires it):

Contract

Section titled “Contract”

@StateContract

Section titled “@StateContract”

Marks a class as a JOUST state contract. The processor generates <Name>Validator (a JuLC @MultiValidator) and <Name>Client in the same package. JuLC treats it exactly like its own @OnchainLibrary (a fixed alias, bloxbean/julc#311), so JuLC compiles the class for on-chain use without a second annotation.

Target: a public top-level class. Source: StateContract.java

Element Type Default Meaning
minAda long 0 Lovelace locked in the state UTxO as its min-ADA deposit, on top of the contract’s funds. 0 derives it (below). An explicit value below the derived one is a compile error
maxDatumBytes int 512 Largest serialised state the validator accepts; a transition that grows the datum past it is rejected, so no call can push the UTxO beyond what minAda covers. Must be 16 to 8192
maxValidityMs long 3_600_000 Widest validity interval (validTo - validFrom, POSIX ms) a call that reads Ctx may use. At least 60000
assetSlots int -1 Native assets a state or object UTxO is expected to hold, for the deposit (about 80 bytes each). -1 means 4 for contracts that handle native assets, 0 otherwise. Must end up 0 to 64
stakeSelf boolean false Stake the state UTxOs to this script (base addresses). Requires a @Withdraw and a @Certify handler

The derived deposit is 4310 * (160 + 200 + maxDatumBytes + 80 * assetSlots) lovelace, rounded up to 0.1 ADA (stakeSelf counts as one more slot, for the longer base address). With the defaults that is 3.8 ADA.

The processor also requires exactly one @Init, and warns when a contract without owned objects has no @Destroy (its deposit would be locked forever).

Guides: State and lifecycle, Fees and script size.

@Params

Section titled “@Params”

Marks the record of a contract’s deploy-time parameters (ADR-0009 D1). They are applied to the script (JuLC partial application), so each parameter set has its own policy id and address. A method receives them by declaring a parameter of this type right after the state (or after @Shared; first in @Init).

Target: a record nested in the contract. Elements: none. Source: Params.java

Rules: at most one @Params record per contract; it cannot hold MerkleMaps. Other annotations name its fields as "params.field" (@Quorum, @AuthorizedBy, @Reads, @Migrate, @MigrateTo). Purpose handlers take it as their first parameter.

Guide: Params, invariants and events.

Lifecycle

Section titled “Lifecycle”

@Init

Section titled “@Init”

The constructor: public static S init(args... [, Ctx]). Exactly one per contract. Deploying an instance mints its one-shot thread token and the validator checks the initial datum equals this method’s result.

Target: method. Elements: none. Source: Init.java

  • Returns the state record, or a result record with state and optionally accepted (an init cannot pay out, send, mint or deposit, and cannot emit events yet).
  • Takes the @Params record first if the contract has one.
  • @SignedBy, @OnlyOwner, @ValidAfter, @ValidBefore, @Quorum and @AuthorizedBy are rejected: they check the current state, which a creation does not have. Use Ctx and Require.that in the body.

@Action

Section titled “@Action”

A state transition: public static S name(S state, args... [, Ctx]), or a result record with a state component and any of payouts, sends, deposits, mint, accepted, events.

Target: method. Elements: none. Source: Action.java

The validator re-runs the method and requires exactly one continuing output with the thread token at the same address, an inline datum equal to the result, and an exact value: what the UTxO held, plus what the call receives, minus what it pays out. An action without Ctx needs no signature and is cheaper.

@Destroy

Section titled “@Destroy”

Ends the instance: public static JulcList<Payout> name(S state, args..., Ctx), or a result record with any of payouts, sends, deposits, mint, accepted and no state. The thread token is burned and the payouts must allocate the contract’s whole balance (ctx.balance(), deposit included).

Target: method. Elements: none. Source: Destroy.java

  • Needs a Ctx parameter.
  • A contract with @Owned objects cannot have a @Destroy (objects that read @Shared state would be locked).
  • With MerkleMaps, the processor warns that a destroy discards the maps’ contents: check MerkleMaps.isEmpty(...).

@View

Section titled “@View”

A read-only query, public static T name(S state, args...). Runs off chain only: no transaction, no validator code.

Target: method. Elements: none. Source: View.java

The first parameter must be the state; the method must return a value and cannot take Ctx.

Guide: State and lifecycle.

Result records

Section titled “Result records”

A method that does more than change state returns a record whose component names say what each part is. The processor accepts only these names:

Component Type Allowed in Meaning
state the state (or owned) record actions, creations (required in actions); never in destroys The next state
payouts JulcList<Payout> actions, destroys Lovelace to key hashes
sends JulcList<Send> actions, destroys Outputs to any address with any datum, claimed in the output registry (ADR-0007)
deposits JulcList<Deposit> actions, destroys Payments into another JOUST instance’s @Receives action (ADR-0011 D3)
mint Value actions, destroys Tokens minted (positive) or burned (negative) under the contract’s own policy
accepted Value @Payable methods with Funds Exactly the native assets the call takes in (required there)
events JulcList of event records not creations, not @Batched Authenticated events, carried in the redeemer and checked equal (ADR-0009 D5)

A destroy’s record needs at least one of payouts, sends, mint, deposits.

Authorization

Section titled “Authorization”

@SignedBy

Section titled “@SignedBy”

The transaction must be signed by the key hash (byte[]) held in the named field of the current state (for owned methods, of the owned record).

Target: method. Source: SignedBy.java

Element Type Default Meaning
value String required Name of a byte[] component of the state record

Not allowed on @Init or @Batched actions. The processor warns when an owned method has no @SignedBy (anyone could call it on anyone’s object).

@OnlyOwner

Section titled “@OnlyOwner”

Shorthand for @SignedBy("owner"): the state needs a byte[] owner component.

Target: method. Elements: none. Source: OnlyOwner.java

@Quorum

Section titled “@Quorum”

M-of-N signatures (ADR-0009 D2): at least threshold (and at least one) of the transaction’s signatories are among keys.

Target: method. Source: Quorum.java

Element Type Default Meaning
keys String required A JulcList<byte[]> field of key hashes: of the state, the owned record, or "params.x"
threshold String required A BigInteger field: of the state, the owned record, or "params.x"

The generated check also requires distinct, strictly ascending 28-byte keys. Not allowed in creations or on @Batched actions. Purpose handlers must name params.* fields.

@AuthorizedBy

Section titled “@AuthorizedBy”

The method needs the approval of a credential (ADR-0009 D3), named by a Credential field of the state, the owned record, or the @Params record ("params.field"). A key credential must sign. A script credential must run in the transaction for a zero withdrawal (the withdraw-zero pattern) and approves by its own rules; a JOUST-aware governor lists its approvals in an Approvals redeemer.

Target: method. Source: AuthorizedBy.java

Element Type Default Meaning
value String required A Credential field: "field" or "params.field"

Not allowed in creations or on @Batched actions.

Guide: Authorization. Tutorial: Multisig treasury.

Time

Section titled “Time”

@ValidAfter

Section titled “@ValidAfter”

The transaction’s validity interval must start at or after the time (POSIX ms) held in the named BigInteger field of the current state. The client sets the interval for you.

Target: method. Source: ValidAfter.java

Element Type Default Meaning
value String required Name of a BigInteger component of the state record

@ValidBefore

Section titled “@ValidBefore”

The transaction’s validity interval must end at or before the time held in the named BigInteger field of the current state.

Target: method. Source: ValidBefore.java

Element Type Default Meaning
value String required Name of a BigInteger component of the state record

Both are rejected on @Init (no current state) and on @Batched actions (the batcher picks the interval). In those, check time in the body with Clock. Guide: Time.

Funds

Section titled “Funds”

@Payable

Section titled “@Payable”

The @Init or @Action (or owned creation or action) may receive lovelace: ctx.received() > 0. Without it, received must be zero. With a Funds parameter it may also take native assets, and must then return a result record with accepted, exactly the native assets it takes.

Target: method. Elements: none. Source: Payable.java

Needs a Ctx parameter.

Guide: Ctx, funds and payouts.

@Receives

Section titled “@Receives”

An action that takes deposits from other JOUST contracts in the same transaction (ADR-0011 D3). Its value equation adds every deposit claimed on its continuing output, and the method sees them in funds.deposits(). An action without it takes no deposits: its exact value check fails if anyone adds value to its output.

Target: method. Elements: none. Source: Receives.java

Rules: only on an @Action or @OwnedAction; needs a Funds parameter; cannot be @Batched.

Guide: Deposits.

Owned objects

Section titled “Owned objects”

Owned objects (ADR-0003, ADR-0012) are records that live in their own UTxOs under an instance, so different objects never contend. Guide: Owned objects. Tutorial: Bank: owned objects.

@Owned

Section titled “@Owned”

Marks a record of the contract as an owned type. Each object is its own UTxO, touched only by owned methods.

Target: a record nested in the contract. Elements: none for a plain owned type; the keyed elements below make it a keyed type. Source: Owned.java

  • A contract may have several owned types since ADR-0012 D1 (the Javadoc’s “at most one” predates it); each gets its own datum variant Holding_<Type>, a single type keeps Holding.
  • Each owned type needs at least one @OwnedInit, and an @OwnedDestroy without @Shared (an escape hatch that works whatever the instance state).
  • MerkleMaps may be direct components of an owned record (ADR-0012 D2), but not of the instance state of a contract with owned objects.
  • A contract with owned objects cannot @Destroy its instance.

Keyed types (ADR-0016). Naming a byte[] component as key makes the type keyed: at most one object per key and instance, in a sorted on-chain list. Guide: Keyed objects.

Element Default Meaning
key "" The byte[] component that keys the object; empty for a plain owned type
maxKeyBytes 32 Longest key: 1 to 64 bytes
signedKey false The key is a 28-byte key hash that must sign the insert
linkCooldownMs 60,000 Least time between two relinks of a node: 0 (written explicitly) or 60,000 to 3,600,000
linkWindowMs -1, meaning min(120,000, maxValidityMs) Widest validity window of a relink: 20,000 to min(900,000, maxValidityMs)

A keyed type needs an @OwnedDestroy(retire = true) signed with @SignedBy, and every keyed @OwnedAction must carry @SignedBy, @Quorum or @AuthorizedBy. Setting a keyed element on a type without key is an error.

@OwnedInit

Section titled “@OwnedInit”

Creates an owned object: public static R name([@Shared S shared,] args... [, Ctx]). The object belongs to the instance it is created under. Returns the owned record (or a record with a state of it).

Target: method. Elements: none. Source: OwnedInit.java

@OwnedAction

Section titled “@OwnedAction”

Changes one owned object: public static R name(R object, [@Shared S shared,] args... [, Ctx]), or a result record with state (the owned record) and effects. Spends only the object’s UTxO.

Target: method. Elements: none. Source: OwnedAction.java

@OwnedDestroy

Section titled “@OwnedDestroy”

Ends an owned object: public static JulcList<Payout> name(R object, [@Shared S shared,] args..., Ctx). Burns its token; the payouts must allocate everything it holds. The processor warns if the object has MerkleMaps (they are discarded).

Target: method. Elements: retire (default false). Source: OwnedDestroy.java

On a keyed type, a plain @OwnedDestroy removes the object and frees its key, and @OwnedDestroy(retire = true) retires it: the object stays as a retired node with its deposit and its key, taken for good, and the payouts allocate exactly ctx.balance() (everything but the deposit). A retiring exit cannot take @Shared, @Reads, @Payable, @Quorum, @AuthorizedBy, @ValidAfter or @ValidBefore.

@Shared

Section titled “@Shared”

Gives an owned method the instance’s state, read-only, through a reference input: the instance is not spent, so it causes no contention (ADR-0003 D1).

Target: parameter. Elements: none. Source: Shared.java

Rules: only on owned methods; the parameter’s type must be the state record; it comes right after the owned record (first in an @OwnedInit).

@Into

Section titled “@Into”

Marks the destination of a move (ADR-0012 D3): an @OwnedAction parameter of the state type, after the @Shared source if any. The object moves to that instance, which is spent in the same transaction by an @Admits action naming the object. The method gets the destination’s state as it was before. The redeemer carries the destination’s id, and both validators check each other’s redeemer (I43).

Target: parameter. Elements: none. Source: Into.java

Rules: only on @OwnedAction; a move returns the owned record (or a record with its state); it cannot take @Reads; an @Into move needs an @Admits action for its type. Moves run only inside Compose.

@Admits

Section titled “@Admits”

An @Action through which an instance admits an object moving in from another instance of the same contract (ADR-0012 D3). Its first argument after the state (and the params) is the object’s id (byte[]). The validator requires that object to be spent in the same transaction with a move naming this instance; the method decides whether to admit it and may update the instance’s state.

Target: method. Source: Admits.java

Element Type Default Meaning
value String "" The owned record it admits ("Hero"). Required when more than one owned type has moves

Rules: only on an instance @Action; cannot be @Batched or take @Reads; the contract needs an @Owned record and an @Into move.

Batching

Section titled “Batching”

@Batched

Section titled “@Batched”

The @Action may also run as an intent (ADR-0004): a user locks a request in their own UTxO, and a batcher applies many requests to the instance in one transaction, so concurrent writers do not contend.

Target: method. Source: Batched.java

Element Type Default Meaning
only boolean false Only as an intent: no direct call, so nobody can invalidate pending batches by spending the instance directly

In a batch, ctx.caller() is the intent’s owner, ctx.received() the amount the intent carries, ctx.balance() the balance at that point of the fold, and validFrom/validTo the batch transaction’s bounds. An intent runs against whatever state the batch finds: take a bound (a minimum out, a maximum price) as an argument and check it.

Rules: only on @Action; needs Ctx; cannot use @SignedBy, @OnlyOwner, @ValidAfter, @ValidBefore, @Quorum, @AuthorizedBy, events, the @Params record, @Reads, Funds, sends, mints or deposits. A contract with @Batched actions cannot also have MerkleMap state, native assets or @Invariants yet.

Guide: Batched intents. Tutorial: Pool: batched intents.

Composition and reads

Section titled “Composition and reads”

@Reads

Section titled “@Reads”

A method parameter that reads another JOUST contract’s instance state through a reference input (ADR-0011 D2). The validator checks the token kind, the single token, the script address and the inline datum’s shape before decoding.

Target: parameter. Source: Reads.java

Element Type Default Meaning
value String required "params.x", naming a ForeignInstance component of the @Params record

Rules: the parameter’s type is the other contract’s state record; @Reads parameters come right after the @Params record; the read state cannot hold MerkleMaps; not supported in creations, moves or @Admits actions yet. Freshness is the reading contract’s job (check a timestamp in the read state).

Guide: Reads and composition. Tutorial: Oracle and composition.

Purposes and governance

Section titled “Purposes and governance”

Purpose handlers (ADR-0010 D1) answer the ledger’s other script purposes for the contract’s own credential. They are public static, take the @Params record first, are governed by @Quorum or @AuthorizedBy over params.* fields (except @Propose), and cannot carry a lifecycle annotation. At most one handler per purpose. Contracts with @Votes or @Propose handlers need -Ajulc.blueprint=false (a CIP-57 vocabulary gap in JuLC).

Guide: Staking and governance. Tutorial: Staked vault and governance.

@Withdraw

Section titled “@Withdraw”

Handles withdrawals of the contract’s staking rewards: (Params cfg, BigInteger amount, args..., [Ctx]) returning JulcList<Send> totalling exactly amount, claimed in the output registry.

Target: method. Elements: none. Source: Withdraw.java

@Certify

Section titled “@Certify”

Decides which certificates of the contract’s credential are allowed: (Params cfg, TxCert cert) returning boolean. Unregistration, committee and pool certificates are refused before it runs. Use the Certs helpers for exact checks.

Target: method. Elements: none. Source: Certify.java

@Votes

Section titled “@Votes”

Decides the contract’s votes as a DRep or committee member: (Params cfg, Voter voter, GovernanceActionId action, Vote vote) returning boolean, called for every vote it casts.

Target: method. Elements: none. Source: Votes.java

@Propose

Section titled “@Propose”

A constitution guardrail: (Params cfg, ProposalProcedure p) returning boolean. The ledger runs it for parameter-change and treasury-withdrawal proposals once a constitution names this script.

Target: method. Elements: none. Source: Propose.java

Upgrades

Section titled “Upgrades”

Version migration (ADR-0011 D4) moves an instance’s state and funds from one contract to its successor in one composed transaction. Neither annotation is supported yet with MerkleMaps, owned objects or native assets. Guide: Upgrades and migration. Tutorial: Upgrading a contract.

@MigrateTo

Section titled “@MigrateTo”

On a @Destroy: the instance migrates to its successor. The validator requires that the successor mints the instance id blake2b_256(own input), and that its output holds at least everything this instance holds, less the payouts.

Target: method (an instance @Destroy). Source: MigrateTo.java

Element Type Default Meaning
value String required A byte[] field holding the successor’s policy: a state field an admin sets, or "params.x"

@Migrate

Section titled “@Migrate”

A creation that adopts an instance of the previous contract version: (Params cfg, Old.State old, args..., [Ctx]) returning the new state. The seed is the old state UTxO, whose token must be burned in the same transaction; the new instance holds exactly the old lovelace and the new token.

Target: method. Source: Migrate.java

Element Type Default Meaning
from String required "params.x", a byte[] field of the @Params record holding the previous policy

Rules: at most one @Migrate per contract; it is its own kind of creation (no other kind annotation); the parameter after the params must be the previous contract’s state record.

Invariants

Section titled “Invariants”

@Invariant

Section titled “@Invariant”

A rule every state must keep (ADR-0009 D4): a static method taking the state (or an owned record), optionally the @Params record, and returning boolean. The validator checks it on every state it accepts as an output (creation and every action); the runtime checks it before submitting.

Target: method. Elements: none. Source: Invariant.java

Rules: static, returns boolean, cannot combine with a lifecycle annotation; cannot read state (or an owned record) with MerkleMaps; a contract with @Batched actions cannot have invariants yet.

Guide: Params, invariants and events.

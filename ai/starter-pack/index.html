AI starter pack

Read this entire document before generating any JOUST code. It states what JOUST is, the shapes the annotation processor accepts, the subset of Java that compiles on chain, the rules that keep the off-chain and on-chain runs in agreement, complete examples taken from the tested contracts in the repository, and the errors agents most often cause. Follow it literally. When something you need is not here, look it up in https://joust.julc.dev/llms-full.txt or https://joust.julc.dev/ai/catalog.json; never invent an annotation, class, method or option.

This pack is written for machine ingestion. For people, start at How JOUST works.

1. What JOUST is

Section titled “1. What JOUST is”
  • JOUST (“State Contract Simplified”, said “jowst”) is a framework for Cardano smart contracts. A contract is a state record plus pure static methods: @Init creates an instance, @Action returns the next state, @Destroy ends an instance and returns payouts, @View reads.
  • The same method runs twice. Off chain (on the JVM, or the Wasm engine in Node or a browser worker) it computes the next state and the client builds the transaction. On chain, JuLC compiles it to UPLC and the generated validator re-runs it and requires the output datum to equal the result.
  • Therefore contract code must give the same answer in both runs. Every rule in section 7 exists for that reason.
  • The annotation processor generates, per contract X:
    • XValidator: a JuLC multi-validator (mint and spend, plus other purposes when used), compiled to UPLC.
    • XClient: a typed Java client on cardano-client-lib (CCL).
    • a description, META-INF/joust/<package>.X.json (CIP-57 plus x-joust), from which typed JavaScript clients are generated.
  • The generated validator enforces, without your code: one-shot thread token per instance; exactly one continuing output at the same address holding the token; inline datum equals the method’s result; exact value (no token dust); a verified Ctx (caller signed, received, balance, validity bounds); payouts tagged against double satisfaction; the token burned on destroy; the datum within maxDatumBytes.
  • Two languages for contracts: Java (a @StateContract class) and .jsc (a contract language that reads like TypeScript, lowered to a Java @StateContract at build time; .jsc is a language preview). Clients: Java (XClient) or JavaScript (X.js, plus X.d.ts).
  • Built on JuLC (Java to UPLC compiler, julc.dev) and cardano-client-lib (CCL). Plutus V3. A JOUST release brings the JuLC and CCL versions it was built with (gradle/libs.versions.toml at its tag).
  • Status: experimental, pre-release, not for production. Never guess a version: take the newest release whose tag starts with v on https://github.com/bloxbean/joust/releases (not the “Development snapshot” entry), or run npm view @julclang/joust version. JOUST’s Maven modules, its Gradle plugin org.julclang.joust and the JuLC they need are in https://repo.bloxbean.org/maven/releases (recent JOUST releases, and JuLC’s, are on Maven Central too); joust new writes a build that uses it. The npm packages (@julclang/joust, @julclang/joust-runtime, @julclang/state-client, create-joust) are on npmjs.org (npm create joust@latest).

3. The contract model

Section titled “3. The contract model”

3.1 Class shape

Section titled “3.1 Class shape”
  • Every contract method is public static, not generic, uniquely named (no overloading).
  • A method has exactly one kind: @Init, @Action, @Destroy, @View, @OwnedInit, @OwnedAction, @OwnedDestroy, or a purpose handler (@Withdraw, @Certify, @Votes, @Propose). Modifiers (@Payable, @OnlyOwner, @SignedBy, @ValidAfter, @ValidBefore, @Quorum, @AuthorizedBy, @Batched, @Receives, @MigrateTo, @Admits) go on top of a kind.
  • Plain static helper methods without an annotation are allowed (they are compiled on chain too).
  • The state record is the return type of @Init. Its name is free (State, Pool, …).

3.2 Parameter order (enforced)

Section titled “3.2 Parameter order (enforced)”
Method Parameters, in this order
@Init [@Params record], arguments…, [Ctx], [Funds]
@Action, @Destroy state, [@Params record], [@Reads foreign states…], arguments…, [Ctx], [Funds]
@OwnedInit [@Shared state], [@Params], arguments…, [Ctx], [Funds]
@OwnedAction, @OwnedDestroy owned record, [@Shared state], [@Into state, moves only], [@Params], arguments…, [Ctx], [Funds]
@View state, arguments… (no Ctx)
@Invariant state (or owned record), [@Params record]; returns boolean
  • Ctx is the last parameter, or the last before Funds. Funds is always last.
  • @Payable needs Ctx. @Destroy needs Ctx (it must pay out ctx.balance()). @Batched needs Ctx.
  • Arguments become redeemer fields: use BigInteger, byte[], boolean, records, JulcList<...>. Never type an argument Value (it mis-decodes on chain): use PlutusData if you must.
  • Reserved parameter names: ctx (only for the Ctx parameter), maps, funds, assetsIn; in @Init also seed and instance.
  • MerkleMap/MapEntry are never parameters (only state components).

3.3 Return shapes (enforced)

Section titled “3.3 Return shapes (enforced)”
Kind Returns
@Init the state record (its return type defines the contract’s state type)
@OwnedInit the owned record, or a record with state (the owned record) and accepted only: a creation cannot pay out, send, mint or emit events
@Action, @OwnedAction the state, or a record with state and any of: payouts (JulcList<Payout>), sends (JulcList<Send>), deposits (JulcList<Deposit>), mint (Value), accepted (Value), events (JulcList<E> of event records)
@Destroy, @OwnedDestroy JulcList<Payout>, or a record without state and with at least one of payouts, sends, deposits, mint
@View any value (not void)
  • Result record components must use exactly these names. Any other name is an error.
  • A @Payable method that takes Funds must return a record with accepted: exactly the native assets it takes in. accepted without @Payable and Funds is an error.

3.4 Ctx and Funds

Section titled “3.4 Ctx and Funds”
Field Meaning
ctx.caller() key hash of the caller; the generated validator requires the transaction to be signed by it
ctx.received() lovelace this call adds (zero unless @Payable)
ctx.balance() in an action: the contract’s lovelace before the call minus the min-ADA deposit; in a destroy: everything the UTxO holds, deposit included; zero in init
ctx.validFrom(), ctx.validTo() the transaction’s validity interval, POSIX ms, [from, to); checked equal to the transaction’s bounds, width at most maxValidityMs
funds.policy() this contract’s policy id (name your own tokens with it)
funds.self() token name of what the method acts on (instance id, or object id)
funds.received() native assets the caller adds (no lovelace), empty unless @Payable
funds.held() native assets the UTxO holds before the call, without lovelace and its own thread token
funds.deposits() deposits from other contracts, only in a @Receives action

A method without Ctx needs no signature and is cheaper (anyone can call it).

3.5 @StateContract elements

Section titled “3.5 @StateContract elements”
Element Type Default Meaning
minAda long 0 (computed) lovelace locked in each state UTxO; 0 computes it from maxDatumBytes and assetSlots; a value below that is an error
maxDatumBytes int 512 largest datum allowed (16 to 8192); checked on chain and by the runtime
maxValidityMs long 3600000 widest validity interval (at least 60000)
assetSlots int -1 native assets a UTxO may hold (0 to 64), for the min-ADA computation
stakeSelf boolean false stake state UTxOs to the contract’s own script; needs @Withdraw and @Certify handlers

4. Annotations (all of them)

Section titled “4. Annotations (all of them)”

All in org.julclang.state.api.

Annotation Target Elements Meaning
@StateContract class see 3.5 marks the contract
@Init method creates an instance (exactly one per contract)
@Action method a state transition
@Destroy method ends the instance, burns its token, pays everything out
@View method an off-chain read
@Payable method the call may receive lovelace (and assets with Funds); needs Ctx
@OnlyOwner method shorthand for @SignedBy("owner")
@SignedBy method String value signed by the key hash in the named byte[] field of the current state
@ValidAfter method String value validity interval starts at or after the time in the named state field
@ValidBefore method String value validity interval ends at or before the time in the named state field
@Quorum method String keys, String threshold M-of-N signatures: keys names a JulcList<byte[]> state field (strictly ascending), threshold a BigInteger field
@AuthorizedBy method String value a script credential ("params.guardian", a Credential of the params) must authorise the call through a zero withdrawal
@Params record deploy-time parameters (one record per contract); each parameter set is its own script
@Invariant method static boolean over the state (and params), checked on every output state
@Owned record an owned object type: each object is its own UTxO
@OwnedInit, @OwnedAction, @OwnedDestroy method create, change, close an owned object
@Shared parameter the instance state, read-only by reference input, in an owned method
@Into parameter marks an @OwnedAction as a move of the object into another instance
@Admits method String value (default "") an instance @Action that admits a moved object (names the owned type when several have moves)
@Batched method boolean only (default false) the action may also run as an intent applied by a batcher; only = true: only as an intent
@Reads parameter String value another contract’s state by reference input; names a ForeignInstance field of the params ("params.oracle")
@Receives method an action that takes deposits from other contracts (needs Funds)
@MigrateTo method String value on an instance @Destroy: migrate to the successor whose policy is in the named byte[] field
@Migrate method String from a creation that adopts a previous contract’s instance (from = "params.previous")
@Withdraw, @Certify, @Votes, @Propose method purpose handlers: reward withdrawals, certificates, DRep votes, proposals (params-governed)

@SignedBy, @OnlyOwner, @ValidAfter, @ValidBefore, @Quorum and @AuthorizedBy read the current state, so they are errors on @Init: check ctx.caller() and use Require.that in the body instead. Full reference: Annotations.

6.3 Token: unbounded balances in a MerkleMap

Section titled “6.3 Token: unbounded balances in a MerkleMap”

The map lives off chain (a Merkle Patricia Forestry trie); the datum holds its 32-byte root. Each call proves only the keys it reads and writes, and a shared withdraw-zero verifier script checks the proofs. The runtime supplies the proofs; your code only calls MerkleMaps helpers.

6.4 Bank: owned objects beside shared state

Section titled “6.4 Bank: owned objects beside shared state”

Owned-object rules: each @Owned type needs at least one @OwnedInit and an @OwnedDestroy without @Shared (the escape hatch: an owner can always close their object). A contract with owned objects cannot have an instance @Destroy. In an owned method @SignedBy/@OnlyOwner name fields of the owned record; without one, anyone can call it on anyone’s object (the processor warns). The @Shared state is read by reference input, so owned objects never contend.

7. Rules (MUST)

Section titled “7. Rules (MUST)”

7.1 The JuLC subset (contract code compiles to UPLC)

Section titled “7.1 The JuLC subset (contract code compiles to UPLC)”
  1. Integers are BigInteger. Never int, long, short, byte, double, float, Integer, Long, and never intValue()/longValue(): the processor’s lint rejects them (“fixed-width numbers diverge between the JVM and on-chain. Use BigInteger”). Compare with compareTo/signum, never ==. Constants: BigInteger.ZERO, ONE, TWO, TEN, BigInteger.valueOf(997).
  2. Data types are records and sealed interfaces with record variants. No classes with fields, no generic records, no enums in contract types.
  3. Locals are immutable (declare a new local instead of reassigning); only loop accumulators may be reassigned.
  4. No throw, try/catch, null, reflection, streams, lambdas stored in variables, Function.apply, varargs.
  5. Call static methods through the imported simple class name (MerkleMaps.getInt(...), not a fully qualified name).
  6. Read a component of a call’s result through a typed local: Account a = f(x); a.balance(), not f(x).balance().
  7. An empty list or map goes into a typed local first: JulcList<Event> none = JulcList.empty();, JulcMap<byte[], BigInteger> none = JulcMap.empty();.
  8. byte[] is a bytestring; boolean and String (messages) are fine.

7.2 JOUST rules

Section titled “7.2 JOUST rules”
  1. Never compare byte[] with == or .equals. On chain they compare bytes, on the JVM references: the two runs disagree. Use ByteStringLib.equals(a, b) (org.julclang.stdlib.lib.ByteStringLib).
  2. Every rule is Require.that(cond, "message"). Use a literal message; it is what the client reports.
  3. Exactly one @Init, returning the state record.
  4. Write a @Destroy (or owned objects with @OwnedDestroy): otherwise every instance’s min-ADA deposit is locked forever (the processor warns). A destroy pays out everything: Payouts.of(owner, ctx.balance()).
  5. Pay out only what the contract holds. Check amount <= ctx.balance() (or a tracked total), and authorise who may take it (@OnlyOwner, @SignedBy, @Quorum, or a ctx.caller() check).
  6. A method without Ctx can be called by anyone, unsigned. Add Ctx (and an authorisation) when the caller matters.
  7. Time: use Clock.after(ctx, t) / Clock.before(ctx, t) or @ValidAfter/@ValidBefore; they hold for the whole validity window. Never compare validFrom/validTo by hand in a way that holds only for part of it.
  8. Inline maps in the state (JulcMap<byte[], BigInteger>) must stay in canonical key order: always update them with SortedMaps.put/remove/getOr. Never JulcMap.insert (it prepends, duplicates stay) and never getOrDefault (not on chain). The runtime refuses a non-canonical state.
  9. MerkleMap rules: a MerkleMap (or MapEntry) only as a direct component of the state record or an owned record; create with MerkleMaps.empty(); read and write only through MerkleMaps helpers; never construct one, never pass one as an argument, never read .reads(), .writes() or .root(). A @Destroy should check MerkleMaps.isEmpty(...) (the processor warns). Not combinable with @Batched, @Invariant, @Reads of map state, @Migrate/@MigrateTo, or instance-level maps beside owned objects.
  10. Size: set maxDatumBytes to the largest state you allow; a state that grows past it fails (on the JVM first). Keep scripts well under the 16 KB transaction limit (several owned types plus moves plus maps exceeded it).
  11. Payouts go to key hashes (paid to the key’s enterprise address). A Send to a person must use an enterprise address (new Address(new Credential.PubKeyCredential(new PubKeyHash(key)), Optional.empty())), never the caller’s fee-paying base address.
  12. @Batched actions need Ctx; ctx.caller() is the intent’s owner. They cannot use @SignedBy, @OnlyOwner, @ValidAfter, @ValidBefore, @Quorum, @AuthorizedBy, events, params, @Reads, Funds, sends or mint. The batcher picks the order and time: take bounds (a minimum out, a maximum price) as arguments and check them. A batch holds about 8 intents.
  13. @Params is one record per contract; a method takes it right after the state (first in @Init). @Quorum key lists must be strictly ascending.
  14. Native assets: a native Value cannot be a loop accumulator (use recursion). Do not cast a record to PlutusData ((PlutusData) (Object) r throws on the JVM); build data with Builtins.constrData/bData/iData.
  15. Do not name a method like a generated client member, or a parameter maps, funds, assetsIn (or seed/instance in @Init); rename when the processor says so.
  16. Contracts with @Votes or @Propose need -Ajulc.blueprint=false.

8. Anti-patterns

Section titled “8. Anti-patterns”

9. .jsc in brief

Section titled “9. .jsc in brief”

.jsc (a preview, ADR-0018) is lowered to a Java @StateContract before compilation (the Gradle plugin’s generateJsc task, or joust build for .jsc files in contracts/). Full reference: .jsc reference; functions: .jsc standard library.

Element Syntax
Header jsc 1 (optional), package a.b.c, import { f } from "std/bytes", then types, enums, fns and one contract Name(maxDatumBytes = 192) { ... }; options minAda, maxDatumBytes, maxValidityMs
State state { owner: Key, goal: Int }; types Int, Bool, Bytes, Key, Hash, List<T>, Option<T>, Map<K, V> (inline, canonical), BigMap<K, Int | Bytes> (a MerkleMap), records, enums
Methods init(args) [payable] { return { ...all fields } }, action name(args) mods { return { ...state, f: e } }, destroy name(args) mods { pay(to, amount) }, view name(args): T = expr
Modifiers payable, only <field>, after <field>, before <field>, open, batched, batched only (an action; never with only/after/before; a paying one says open; not with BigMap state)
Statements const x = e, require(cond, "message"), pay(to, amount), if c { } else { }, match e { P => … }, for (const x of xs) { }
Expressions c ? a : b, if/match as values, o ?? d, { ...state, f: e }, Type { f }, [a, ...xs], xs.fold(0, (acc, x) => acc + x), m[k] on a BigMap<K, Int>
Context caller, received, balance, validFrom, validTo (not in views or fns)
Prelude min, max, abs, utf8("…"), asKey(b), asHash(b), range(a, b), Some(x), None, after(t), before(t)
Literals 42, 1_000, 5 ada (times 1,000,000), #deadbeef (bytes), true, false, "text" (messages and utf8 only)
Comments // ..., /* ... */
  • Values are immutable: no let, var, =, += or ++ (each is an error naming the fix). A block’s value is its last expression.
  • An action that can pay needs only <key field>, or open to say anyone may call it.
  • after(t) and before(t) only at the top of a require (alone, or under &&/||). A value computed from validFrom/validTo never decides a branch and never makes an operation fail.
  • <Contract>.abi.json is committed beside the .jsc file; a missing or changed one fails the build (JSC0003, JSC0002) until accepted (joust build --accept-abi, Gradle acceptJscAbi).

10. Error to fix

Section titled “10. Error to fix”
Message (or symptom) Cause Fix
'int' in a @StateContract ... Use BigInteger / fixed-width arithmetic int/long/double or intValue() in contract code Use BigInteger everywhere
a @StateContract needs exactly one @Init method, found N none or several @Init Exactly one @Init
@Init must return the state record @Init returns something else Return the state record (it defines the state type)
contract methods must be public static instance method or not public public static
contract method names must be unique (no overloading) overloads Rename

11. Checklist before submitting code

Section titled “11. Checklist before submitting code”
  1. Is every number BigInteger, compared with compareTo/signum?
  2. Is every byte[] comparison ByteStringLib.equals?
  3. Is every rule a Require.that(cond, "literal message"), with no throw, null or try?
  4. Are all locals assigned once (loop accumulators aside)?
  5. Is there exactly one @Init, returning the state record, and a @Destroy (or owned escape hatches)?
  6. Do parameters follow the order: state, [params], [reads], arguments, [Ctx], [Funds]? Does every @Payable, @Destroy and @Batched method take Ctx?
  7. Does each action return the state, or a record whose component names are exactly state, payouts, sends, deposits, mint, accepted, events?
  8. Is every payout authorised and bounded by what the contract holds?
  9. Are inline state maps updated only through SortedMaps, and MerkleMaps only through MerkleMaps?
  10. Is maxDatumBytes large enough for the largest state the rules allow?
  11. Does every annotation, class and method you used appear in sections 4 and 5 (or in /ai/catalog.json)?
  12. Did you write JVM tests for each method and each rule, and, with julc-state-testkit, harness tests with Attacks.assertAllRejected? Did you run ./gradlew build (or npx joust build && npm test)?

If any answer is no, fix the code before you present it.

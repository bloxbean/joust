# Security Policy

## Project status

JOUST is an experimental research project. Do **not** use it in production or with real funds on Cardano mainnet.
Its validators are compiled by [JuLC](https://github.com/bloxbean/julc), which is experimental too.

## Reporting a vulnerability

If you find a security vulnerability in JOUST, please report it privately:

1. **Do not** open a public GitHub issue, discussion or pull request for it.
2. Email your report to **security at bloxbean.com**.
3. Include:
   - a description of the vulnerability and the affected module or package (and version or commit);
   - steps to reproduce: ideally a contract and a transaction, or a failing test (the on-chain harness,
     `StateHarness`, and the attack suite in `julc-state-testkit` are good starting points);
   - the impact, for example a validator that accepts a transaction it should reject, or locked or stolen funds;
   - a suggested fix, if you have one.

We will acknowledge your report and keep you informed while we investigate and fix it.

## Scope

Security-relevant issues include:

- **Generated validators**: a validator generated by `julc-state-processor` (from Java or `.jsc`) that accepts a
  transaction breaking one of the invariants it is meant to enforce: the thread token, the exact datum and value,
  the caller's signature, payouts, owned and keyed objects, MerkleMap claims, batched intents, params, quorums or
  composition.
- **Off-chain checks that protect a signer**: the JavaScript page verifier in `@julclang/state-client` and
  `@julclang/joust-runtime` (what a CIP-30 wallet is asked to sign), the designated-input retry records, and the
  prepare service (`julc-state-server`).
- **Divergence between the JVM and on-chain**: the same contract method computing a different result on the JVM
  than in its compiled script, where that lets a transaction through or locks funds.
- **Serialization**: datum, redeemer or transaction encodings that produce invalid or ambiguous on-chain data.
- **Supply chain**: the published Maven artifacts, the npm packages and their Wasm engines, and the release
  workflows.

Out of scope:

- Compiler bugs in JuLC itself: report them to JuLC (see its
  [SECURITY.md](https://github.com/bloxbean/julc/blob/main/SECURITY.md)). If you are not sure which project is
  affected, report to the address above.
- Limits documented in the ADRs (`docs/adr/`), unless they affect fund safety in a way the ADR does not describe.
- Script size, execution budgets and performance.
- The example contracts under `examples/` used as they are: they demonstrate features and are not audited.
- Feature requests.

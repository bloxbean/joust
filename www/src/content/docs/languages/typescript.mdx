<Aside type="caution" title="Experimental">
The npm path runs JOUST's toolchain and runtime as WebAssembly built with GraalVM Web Image, which is itself experimental. Java with Gradle and cardano-client-lib is the supported, first-class path: see [Quick start: Java](/start/quick-start-java/).
</Aside>

JOUST contracts are written in Java or `.jsc`, not TypeScript. But every contract comes with TypeScript types for the
code that calls it: `joust build` (or `joust-gen`) writes `<Contract>.d.ts` next to the generated client, from the
contract's description. Your editor then knows each method, its arguments and the shape of the state, and `tsc`
catches a misspelt argument or a `number` where bytes were expected.

## The generated `.d.ts`

The template's Counter:

```java title="contracts/app/Counter.java (abridged)"
public record State(BigInteger count, byte[] owner) {}

@Init public static State init(Ctx ctx) { ... }
@Action public static State increment(State s, BigInteger by) { ... }
@Action @OnlyOwner public static State reset(State s) { ... }
@Destroy @OnlyOwner public static JulcList<Payout> close(State s, Ctx ctx) { ... }
```

gives:

```ts title="build/joust/Counter.d.ts"
// GENERATED by joust-gen from app.Counter. Do not edit.
import type { JoustContract, JoustOptions, CallResult, Cip30Api, Pay, Int, Hex, DataHex } from '@julclang/state-client';

export type Ctx = { "caller": Hex; "received": bigint; "balance": bigint; "validFrom": bigint; "validTo": bigint };
export type CtxIn = { "caller": Hex; "received": Int; "balance": Int; "validFrom": Int; "validTo": Int };
export type CounterValidatorCalls = { $variant: "Increment"; "by": bigint } | { $variant: "Reset" } | { $variant: "Close"; "ctx": Ctx };
export type CounterValidatorCallsIn = { $variant: "Increment"; "by": Int } | { $variant: "Reset" } | { $variant: "Close"; "ctx": CtxIn };
export type TxOutRef = { "txId": Hex; "index": bigint };
export type TxOutRefIn = { "txId": Hex; "index": Int };
export type CounterValidatorLifecycle = { $variant: "CreateInstance"; "seed": TxOutRef; "ctx": Ctx } | { $variant: "BurnInstance" };
export type CounterValidatorLifecycleIn = { $variant: "CreateInstance"; "seed": TxOutRefIn; "ctx": CtxIn } | { $variant: "BurnInstance" };
export type CounterState = { "count": bigint; "owner": Hex };
export type CounterStateIn = { "count": Int; "owner": Hex };
export declare const description: unknown;

export declare class Counter {
  constructor(o: JoustOptions);
  readonly contract: JoustContract;
  deploy(wallet: Cip30Api, args: Record<string, never>): Promise<CallResult & { instance: CounterInstance }>;
  at(instanceId: Hex): CounterInstance;
}
export declare class CounterInstance {
  readonly id: Hex;
  read(): Promise<{ ref: string; state: CounterState; lovelace: bigint } | null>;
  state(): Promise<CounterState | null>;
  increment(wallet: Cip30Api, args: { "by": Int }): Promise<CallResult>;
  reset(wallet: Cip30Api, args?: Record<string, never>): Promise<CallResult>;
  close(wallet: Cip30Api, args?: Record<string, never>): Promise<CallResult>;
}
```

There is one type per definition in the description (the state, the redeemers, `Ctx` and the ledger types they use),
then the client's classes.

### Type names

Each definition gets the shortest name that is unique: its key without the contract's package, with dots removed
(`app.Counter.State` becomes `CounterState`, `app.CounterValidator.Calls` becomes `CounterValidatorCalls`). Types from
other packages keep their simple name (`org.julclang.state.api.Ctx` becomes `Ctx`). A clash gets a leading `_`.

### Output types and `In` types

Every type comes twice:

- **`T`**, what JOUST gives you back (decoded state, reports): integers are `bigint`.
- **`TIn`**, what you may pass in (arguments): integers are `Int`, that is `bigint | number | string`.

So `increment(wallet, { by: 5n })`, `{ by: 5 }` and `{ by: '5' }` all type-check, and `state().count` is always a
`bigint`. A `number` must be a safe integer and a string a decimal integer; anything else is refused when the call is
encoded.

### Schemas to TypeScript

| Description schema | Java | TypeScript (`T`) | TypeScript (`TIn`) |
|---|---|---|---|
| `integer` | `BigInteger` | `bigint` | `Int` |
| `bytes` | `byte[]` | `Hex` (lowercase hex `string`) | `Hex` |
| `list` | `JulcList<X>` | `Array<X>` | `Array<XIn>` |
| `map` | `JulcMap<K, V>` (kept sorted: `SortedMaps`) | `Array<[K, V]>` | `Array<[KIn, VIn]>` |
| constructor (record) | a record | `{ "field": ... }` | the same, with `In` fields |
| sum (sealed interface) | sealed variants | a union of `{ $variant: "Name"; ... }` | the same, with `In` fields |
| `Bool` | `boolean` | `boolean` | `boolean` |
| `Optional` | `Optional<X>` | `X \| null` | `XIn \| null` |
| anything else (`Data`) | `PlutusData` | `DataHex` (hex CBOR) | `DataHex` |

These follow the [JSON conventions](/apps/javascript-clients/#json-conventions) the client encodes with. A `$variant`
is the variant's constructor title, for example `{ $variant: "Increment", by: 1n }`.

### Methods

| Contract element | Generated |
|---|---|
| `@Init` | `C.deploy(wallet, args, pay?)`: `Promise<CallResult & { instance: CInstance }>` |
| `@Action`, `@Destroy` | `CInstance.<name>(wallet, args, pay?)`: `Promise<CallResult>` |
| `@Payable` | a required `pay: Pay` parameter |
| `@Quorum`, `@AuthorizedBy` | a further `opts?: { cosigners?: Cip30Api[]; governor?: { governor: { script, hash }; signers?: Cip30Api[] } }` |
| `@Batched` | the method submits an intent |
| owned types | creation methods returning `{ object: C<Type>Object }`, a lookup method, `objects()`, and a class `C<Type>Object` |

`args` is optional (`args?`) when the method takes no arguments and is not payable. For an owned type, `examples/bank`
gives:

```ts title="Bank.d.ts (excerpt)"
export declare class BankInstance {
  readonly id: Hex;
  read(): Promise<{ ref: string; state: BankState; lovelace: bigint } | null>;
  state(): Promise<BankState | null>;
  setPaused(wallet: Cip30Api, args: { "paused": boolean }): Promise<CallResult>;
  setLimit(wallet: Cip30Api, args: { "withdrawLimit": Int }): Promise<CallResult>;
  open(wallet: Cip30Api, args: Record<string, never>, pay: Pay): Promise<CallResult & { object: BankAccountObject }>;
  account(objectId: Hex): BankAccountObject;
  objects(): Promise<Array<{ id: Hex; type: string; value: unknown; lovelace: bigint }>>;
}
export declare class BankAccountObject {
  readonly id: Hex;
  read(): Promise<{ ref: string; type: string; value: BankAccount; lovelace: bigint } | null>;
  deposit(wallet: Cip30Api, args: Record<string, never>, pay: Pay): Promise<CallResult>;
  withdraw(wallet: Cip30Api, args: { "amount": Int }): Promise<CallResult>;
  close(wallet: Cip30Api, args?: Record<string, never>): Promise<CallResult>;
}
```

## The packages' types

`@julclang/state-client` and `@julclang/joust-runtime` ship declarations (`src/index.d.ts`, the `types` of their main
export). The ones you use most:

| Type | Package | What it is |
|---|---|---|
| `Int`, `Hex`, `DataHex` | state-client | `bigint \| number \| string`; hex strings |
| `Pay` | state-client | `{ lovelace?: Int; assets?: AssetsJson }` |
| `Cip30Api` | state-client | the CIP-30 calls the client uses |
| `JoustOptions` | state-client | `{ deployment, service, chain, limits?, onReview? }` |
| `CallResult`, `Report`, `Review` | state-client | a call's result, the verifier's report, what `onReview` gets |
| `Deployment` | both | a contract's deployment |
| `ChainProvider`, `ProviderUtxo`, `Chain` | state-client | a chain provider, its UTxO, the chain view |
| `VerificationError` | state-client | `problems: string[]; report: Report` |
| `JoustRuntime`, `Clock`, `BuiltContract`, `BuiltValidator`, `Governor`, `MapMirror`, `MirrorCache` | joust-runtime | the Node runtime and its parts |

## Typing a page

Vite transpiles `.ts` files (it does not type-check them: run `tsc --noEmit` for that), so a page can be TypeScript:
rename `page/main.js` to `main.ts` and point `index.html` at it. The generated client's types come from `../build/joust/Counter.d.ts`. Two modules a page imports
ship no declarations yet: `virtual:joust/network` (from the Vite plugin) and `@julclang/joust-runtime/page`. Declare
them yourself, from their documented shapes:

```ts title="page/joust-env.d.ts"
declare module 'virtual:joust/network' {
  import type { Deployment } from '@julclang/state-client';
  const net: {
    network: string;
    networkId: number;
    chain: string;
    clock: { zeroSlot: number; zeroTimeMs: number; slotLengthMs: number };
    ttlMs: number;
    explorer: string | null;
    deployments: Record<string, Deployment>;
    contracts: unknown[];
    validators?: unknown[];
    engine: { url: string; integrity?: { script: string; wasm: string } };
  };
  export default net;
}

declare module '@julclang/joust-runtime/page' {
  import type { Service } from '@julclang/state-client';
  export function engineWorker(worker: Worker, options: object): Service & {
    ready: Promise<unknown>;
    mapValue(root: string, key: string, units?: string[]): Promise<string | null>;
    deployments(d: object): Promise<unknown>;
    terminate(): void;
  };
}
```

Then the page type-checks against the generated client:

```ts title="page/main.ts"
import { blockfrostChain, type Cip30Api } from '@julclang/state-client';
import { engineWorker } from '@julclang/joust-runtime/page';
import { Counter, type CounterState } from '../build/joust/Counter.js';
import net from 'virtual:joust/network';

const chain = blockfrostChain(new URL(net.chain, location.href).href);
const service = engineWorker(new Worker(new URL('./engine.worker.js', import.meta.url), { type: 'module' }), net);
const counter = new Counter({ service, chain, deployment: net.deployments['app.Counter'] });

export async function bump(wallet: Cip30Api, id: string): Promise<bigint | undefined> {
  const inst = counter.at(id);
  await inst.increment(wallet, { by: 1n });
  const s: CounterState | null = await inst.state();
  return s?.count;
}
```

<Aside type="note" title="Gaps in the shipped declarations">
The packages' `index.d.ts` files cover the main API but not every export: in `@julclang/state-client`, for example,
`runComposed`, `verifyComposed`, `walletView` and the address helpers are exported but not declared, and
`JoustInstance` lacks `intent`, `cancelIntent`, `batch`, `pendingIntents` and the `opts` of `call`. `Service`
declares a `view` method that `engineService` and `engineWorker` do not have (only `httpService` does), which is why
the declaration above types `engineWorker` as a `Service`. In `@julclang/joust-runtime`, `JoustRuntime` lacks
`compose`. The [reference pages](/reference/state-client/) list every
export with its signature from the source.
</Aside>

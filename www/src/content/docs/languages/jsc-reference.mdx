## Lexical rules

| Element | Rule |
|---|---|
| Version line | The first word of the file, after whitespace and comments, is `jsc`, followed by `2` (`JSC0112`, `JSC0113`). A file whose first word is anything else is v1 |
| Line ends | LF or CRLF only. A lone CR, NEL, U+2028, U+2029, VT and FF are refused (`JSC0147`): some editors break lines there and a `//` comment could hide the code after them |
| Format characters | No Unicode format character (category Cf: the bidirectional controls, zero-width characters) anywhere in the file, comments and strings included (`JSC0145`); a leading byte-order mark is allowed |
| Comments | `//` to the end of the line, and `/* … */` |
| Identifiers | `[A-Za-z_][A-Za-z0-9_]*`: ASCII only (`JSC0146`), so no two names can look alike. Case-sensitive |
| Integers | Decimal digits, `_` between groups (`1_000_000`). No sign: `-5` is unary minus. `5 ada` is 5,000,000 |
| Bytes | `#` then an even number of hex digits (`#cafe`, `JSC0102`); upper case is lower-cased |
| Strings | `"…"` on one line, with the escapes `\"`, `\\` and `\n`; no control characters (`JSC0104`). Only `require` messages and `utf8("…")` arguments |
| Separators and newlines | Newlines do not end statements: a statement ends where its expression cannot continue, or at `;` (optional). Two tokens look at the line: a `[` or a `(` continues an index or a call only on the line of what it follows, so `m[k]` and `f(x)` start on one line, and on a later line `[` or `(` starts a new expression. A line that starts with a binary `-` continues the expression above it (a subtraction) and warns `JSC9007`: join the lines, parenthesise, or end the line above with `;` |

## Grammar at a glance

```text
file      = "jsc" "2" "package" seg { "." seg } { import | type | enum | fn } contract { import | type | enum | fn }
library   = "jsc" "2" "library" seg { "." seg } { import | type | enum | fn }
import    = "import" "{" Ident { "," Ident } "}" "from" String     (String: "std/…", a relative "./x.jsc", or "java:<class>")
type      = "type" Name "=" "{" { field [","] } "}"
enum      = "enum" Name "{" { Name [ "{" { field [","] } "}" ] [","] } "}"
field     = Ident ":" typeRef
typeRef   = Ident [ "<" typeRef { "," typeRef } ">" ]
fn        = "fn" Ident params ":" typeRef ( "=" expr | block )
contract  = "contract" Name [ "(" option { "," option } ")" ] "{" { member } "}"
option    = ( "minAda" | "maxDatumBytes" | "maxValidityMs" ) "=" Int [ "ada" ]
member    = "state" "{" { field [","] } "}"          (exactly once)
          | "init" params [ "payable" ] block
          | ( "action" | "destroy" ) Ident params { modifier } block
          | "view" Ident params ":" typeRef ( "=" expr | block )
          | fn | type | enum
params    = "(" [ Ident ":" typeRef { "," Ident ":" typeRef } ] ")"
modifier  = "payable" | "open" | "batched" [ "only" ] | ( "only" | "after" | "before" ) Ident
block     = "{" { stmt } [ [ "return" ] expr ] "}"
stmt      = "const" Ident [ ":" typeRef ] "=" expr
          | "require" "(" expr "," String ")"
          | "pay" "(" expr "," expr ")"
          | "if" expr block [ "else" ( if | block ) ]
          | "match" expr "{" { pattern "=>" ( block | require | pay | expr ) [","] } "}"
          | "for" "(" "const" Ident "of" expr ")" block
pattern   = "_" | "None" | "Some" "(" Ident ")" | Name [ "{" Ident [ ":" Ident ] { "," … } "}" ]
expr      = see the operator table; primaries: Int [ "ada" ], Hex, "true", "false", Ident, Ident "(" args ")",
            "(" expr ")", "[" [ expr { "," expr } ] [ "," "..." expr ] "]", "{" [ "..." expr "," ] inits "}",
            Name "{" inits "}", if-expression, match-expression
args      = argument { "," argument };   argument = expr | Ident "=>" body | "(" [ Ident { "," Ident } ] ")" "=>" body
```

A file holds one contract (`JSC0114`), a contract one `state` block (`JSC0121`) and exactly one `init` (`JSC0401`).
Members may come in any order. A block's last expression is its value; a statement after it is `JSC0127`.

## Contract options

| Option | Java element | Default | Meaning |
|---|---|---|---|
| `minAda` | `long minAda()` | derived from `maxDatumBytes` | Lovelace locked as the state UTxO's min-ADA deposit; below the derived value is a compile error |
| `maxDatumBytes` | `int maxDatumBytes()` | `512` | Largest serialised state the validator accepts |
| `maxValidityMs` | `long maxValidityMs()` | `3600000` | Widest validity interval a call that reads the transaction may use |

Values are non-negative integer literals (`ada` allowed); anything else is `JSC0402` or `JSC0403`.

## Types and their encodings

The encoding is fixed and is what the [ABI manifest](#the-abi-manifest) states. It is JuLC's encoding of the generated
Java, so a `.jsc` contract and a Java contract with the same state agree on chain.

| `.jsc` | Java | On-chain data (manifest `data`) | Notes |
|---|---|---|---|
| `Int` | `BigInteger` | integer (`int`) | unbounded on both sides |
| `Bool` | `boolean` | `Constr 0 []` false, `Constr 1 []` true (`bool`) | |
| `Bytes` | `byte[]` | bytes (`bytes`) | `<`, `<=`, `>`, `>=` compare bytes |
| `Key` | `byte[]` | bytes, 28 of them (`bytes28`) | a `Key` is a `Bytes`; the reverse only through `asKey` |
| `Hash` | `byte[]` | bytes, 28 of them | a script hash or policy id; `asHash` |
| `List<T>` | `JulcList<T>` | list (`list<…>`) | |
| `Option<T>` | `Optional<T>` | `Constr 0 [x]` / `Constr 1 []` (`option<…>`) | `Option<Option<T>>` is refused (`JSC0305`) |
| `Map<K, V>` | `JulcMap<K, V>` | map with unique keys in canonical order (`map<…>`) | `K` is `Bytes`, `Key` or `Hash`, at most 64 bytes (`JSC0308`) |
| `BigMap<K, Int>`, `BigMap<K, Bytes>` | `MerkleMap` | the `MerkleMap` record: its root, and the reads and writes of the call (`merkleMap<…>`) | a state field only (`JSC0803`) |
| `type R = { f: T, … }` | a generated record | `Constr 0` with the fields in declaration order | no generic records |
| `enum E { A, B { x: Int } }` | a generated sealed interface and one record per variant | `Constr i`, `i` the variant's declaration index, then its fields | |

There are no strings at run time, no implicit conversions, no `null` and no generic user types. Type, enum and variant
names start with a capital (`JSC0205`), have no `_` (`JSC0206`), share one namespace (`JSC0910`), and may not be a
name the processor generates (`Lifecycle`, `Calls`, `Step`, `Funds`, … : `JSC0220`).

### Checked inputs

Every `init` argument and every action and destroy parameter (the redeemer) is checked by generated code before the
method's body runs, recursively through records, enums, lists and options: every `Key` and `Hash` is 28 bytes, and
every `Map` has unique keys of at most 64 bytes in strictly ascending canonical order. A failure is a located
`require` failure. View parameters are not checked: a view runs off chain on your own inputs.

## Names and scope

- A name is bound once and never redeclared or shadowed (`JSC0212`).
- In an action, destroy or view, no parameter, `const`, lambda parameter, loop variable or `match` binding may take a
  state field's name or a built-in's (`caller`, `received`, `balance`, `validFrom`, `validTo`, `state`, `params`,
  `funds`): `JSC0213`. In an `init`, which has no input state, parameters may share the names of the fields it
  creates.
- No binding and no state field takes the name of a declared type, enum, variant or `fn` (`JSC0222`): `const Open:
  Phase = phase` would make `phase == Open` always true.
- Names cannot contain `__` (`JSC0210`) or be Java keywords and literals, members of `Object`, or names the generated
  code uses (`ctx`, `State`, `Outcome`, `deploy`, `instance`, `seed`, `ByteStringLib`, `Int`, `List`, `Option`, …:
  `JSC0211`). The full list is `RESERVED` in `Checker.java`.
- The generated client binds `s` and `r` in actions and destroys, `s` in views, and `seed` and `result` in an
  `init`; a parameter may not take them (`JSC0216`).

## Members

| Member | Generated Java | Rules |
|---|---|---|
| `state { … }` | `public record State(...)`, components in order | at least one field (`JSC0303`) |
| `init(params) [payable] { … }` | `@Init public static State init(params[, Ctx ctx])` | returns the first state (`JSC0410`); only `payable` (`JSC0405`); cannot pay (`JSC0404`) |
| `action name(params) mods { … }` | `@Action public static State name(State s__, params[, Ctx ctx])`, or a record of the state and its payouts when it pays | returns the next state (`JSC0410`) |
| `destroy name(params) mods { … }` | `@Destroy public static JulcList<Payout> name(State s__, params, Ctx ctx)` | no result (`JSC0411`); must pay at least once (`JSC0409`); cannot be `payable` (`JSC0406`) |
| `view name(params): T = expr` | `@View public static T name(State s__, params)` | no transaction built-ins (`JSC0415`), no `pay` |
| `fn name(params): T = expr` | a `static` method of the contract class | pure: no state, no built-ins, no `pay` |

Method names are unique, and a `fn` may not share one (`JSC0202`). A method gets `Ctx ctx` when it is a destroy, has a
modifier other than `open` and `only`, or mentions `caller`, `received`, `balance`, `validFrom`, `validTo`, `after` or
`before`.

## Modifiers

| Modifier | Annotation | Allowed on | Field type |
|---|---|---|---|
| `payable` | `@Payable` | `init`, `action` | |
| `only f` | `@SignedBy("f")` | `action`, `destroy` | `Key` (`JSC0311`) |
| `after f` | `@ValidAfter("f")` | `action`, `destroy` | `Int` |
| `before f` | `@ValidBefore("f")` | `action`, `destroy` | `Int` |
| `open` | none | `action`, `destroy` | |
| `batched` | `@Batched` | `action` (`JSC0418`) | |
| `batched only` | `@Batched(only = true)`: intent-only, no direct call | `action` | |

Modifiers name state fields, never parameters (`JSC0310`). Each is given at most once (`JSC0416`). A `batched` action
cannot also have `only`, `after` or `before` (`JSC0417`): the batcher signs a batch and sets its window, so check the
caller or the time in the body. A paying one says `open` (`JSC0420`): an intent authorises its action until its
deadline, against the state a batcher applies it to, in the batcher's order, so keep deadlines short and bound
order-sensitive arguments. A contract with `BigMap` state cannot have batched actions (`JSC0419`). `batched only`
followed by an identifier that is not a modifier reads as `batched` plus `only f` (then refused), and the six modifier
words are no field or binding name (`JSC0211`).

## Statements

| Statement | Meaning | Rules |
|---|---|---|
| `const x = e`, `const x: T = e` | binds `x` | must be used (`JSC0215`) |
| `require(cond, "msg")` | fails the call unless `cond` holds | the message is a string literal (`JSC0131`) |
| `pay(to, amount)` | a payout of `amount` lovelace to the `Key` `to` | only in an action or destroy, not in a value block, `fn`, view or lambda (`JSC0413`); 0 is skipped, negative fails |
| `if c { … } else { … }` | branches; `else if` chains | as a statement, its arms end in statements (`JSC0314`) |
| `match e { … }` | branches by case | exhaustive (`JSC0924`); as a statement, its arms end in statements |
| `for (const x of xs) { … }` | runs the body per element, in order | the body has no value (`JSC1011`); effects in it accumulate in list order |

A block used as a value (a lambda's block, a value `if` or `match` arm) holds only `const` and `require` statements
(`JSC0315`).

## Expressions

### Operators and precedence

Lowest first. Binary operators are left-associative; comparisons do not chain (`JSC0134`).

| Level | Operators | Operands | Notes |
|---|---|---|---|
| 1 | `c ? a : b` | `Bool` condition | lazy: only the taken arm runs |
| 2 | `o ?? d` | `Option<T>`, `T` | `d` runs only when `o` is `None`; not mixed with `&&`/`\|\|` without parentheses (`JSC0132`); `None ?? d` is `JSC0337` |
| 3 | `\|\|` | `Bool` | lazy |
| 4 | `&&` | `Bool` | lazy |
| 5 | `==`, `!=` | comparable values of one type | structural, through generated helpers; `===` is `JSC0133` |
| 6 | `<`, `<=`, `>`, `>=` | two `Int`s or two `Bytes` (`JSC0334`) | |
| 7 | `+`, `-` | `Int` | |
| 8 | `*`, `/`, `%` | `Int` | `/` truncates toward zero (`QuotientInteger`), `%` takes the dividend's sign (`RemainderInteger`), as JavaScript's `BigInt`; a zero divisor fails. `div` and `mod` in `std/math` floor |
| 9 | `!`, unary `-` | `Bool`, `Int` | |
| 10 | `x.f`, `x.m(args)`, `m[k]` | | a field, a property or a method; `m[k]` on a `BigMap<K, Int>` |

### Equality

`==` and `!=` are defined on `Int`, `Bool`, `Bytes`, `Key`, `Hash`, lists, maps, options, records and enums whose
components are comparable. They lower to generated helpers: field by field, `ByteStringLib.equals` on bytes,
`compareTo == 0` on integers, element by element on lists and maps, tag then fields on enums and options. No `.jsc`
equality is Java `equals` or a reference comparison. `xs.contains`, `indexOf`, `m.get`, `m.has` use the same rules. A
`BigMap`, or a state holding one, is not comparable (`JSC0812`): it is a witness of a Merkle root, not its contents.

### Laziness

Only the taken arm of `if`, `match` and `?:`, the needed side of `&&` and `||`, and the default of `??` when the
option is empty run, on the JVM and on chain. A division, a failing `require` or a map read in an untaken branch
never happens.

### Lists, maps and options

| On | Members |
|---|---|
| `List<T>` | `length`, `isEmpty`, `head` (properties); `contains(x)`, `any(f)`, `all(f)`, `find(f)` (`Option`), `filter(f)`, `map(f)`, `fold(init, (acc, x) => …)`, `sum()` (`List<Int>`), `reverse()`, `concat(ys)`, `take(n)`, `drop(n)` (`n < 0` fails). Literals `[a, b]`, `[x, ...rest]` (the spread last) |
| `range(a, b)` | `any`, `all`, `fold`, `filter`, `map` and `for … of` only (`JSC1009`) |
| `Map<K, V>` | `Map.empty()`; `get(k)` (`Option`), `has(k)`, `set(k, v)`, `delete(k)`, `size`, `keys`, `values`, `isEmpty`, `any((k, v) => …)`, `all(…)`, `fold(init, (acc, k, v) => …)`, in key order. `set` checks the key's length |
| `BigMap<K, V>` | `get(k)`, `has(k)`, `m[k]` (`BigMap<K, Int>`: 0 when absent), `set(k, v)`, `delete(k)`, `isEmpty` (a destroy only), `BigMap.empty()` (an `init` only). See [BigMap rules](#bigmap-rules) |
| `Option<T>` | `Some(x)`, `None`, `o ?? d`, `match` |

Lambdas are only direct arguments of these methods: `x => e`, `(acc, x) => e`, or a value block. They capture
`const`s and cannot be stored or returned.

## Effects and audiences

`pay` is the only effect in `.jsc` 2 today; `send`, `mint`/`burn`, `deposit`, `accept` and `emit` arrive in M2.
Payouts accumulate **in source order** (in a `for`, in list order; an effect in an untaken branch does not happen).
An action that can reach a `pay` in any arm or loop must have `only <field>` or `open` (`JSC0408`).

## Time (D11)

`validFrom` and `validTo` are the only sources of *time values*. A value is a time value if it depends on one through
any expression (`min`, `max` and `abs` included), a `const`, a `fn` argument, a record, list, map or option, a lambda
or `match` binding, or a **time field**: a state field any method sets to a time value, contract-wide (the ABI
manifest lists them as `timeFields`).

- **Deciding.** A time value may not be a condition of `if`, `?:` or `require`, an operand of `&&`, `||` or `!`, a
  collection predicate, or a comparison whose result is used (`JSC0502`, `JSC0514`). The only comparisons with time
  are `after(t)` and `before(t)`, which hold for the whole window and are allowed only as the condition of a `require`
  or an operand of `&&` or `||` at its top (`JSC0506`); never under `!`, in an `if`, a `?:`, a `const`, a `fn` or a
  lambda (`JSC0504`), nor in a view (`JSC0503`). `t` may be a stored time, but not one computed from this call's window (`JSC0505`:
  `after(validFrom - 1)`).
- **Shapes are never time values**: a value's constructor, an option's presence, a list's length and a map's keys.
  So `match` may scrutinise a value holding a time value (its bindings stay time values), and `xs.isEmpty`,
  `m.has(k)` and `== None` are ordinary.
- **Failing.** A time value may not be a divisor (`JSC0515`), a domain-checked `std` argument (`JSC0509`), a map key
  (`JSC0517`), a range bound (`JSC0516`), a `take`/`drop` count (`JSC0512`), an `nth` index (`JSC0510`), a `Key` or
  `Hash` conversion (`JSC0507`) or a `BigMap<K, Int>` value (`JSC0518`). A `fn` called with a time argument is checked
  with that parameter as a time value.
- **Flowing.** Arithmetic on time values is allowed, and they may set state and amounts. A payout set by one must be
  exactly `pay(to, max(0, …))` (`JSC0501`). Warnings name the bias: a stored window value (`JSC9003`), a value derived
  from a stored time (`JSC9004`), a payout (`JSC9005`).

The submitter chooses the window, within `maxValidityMs`: `validFrom` can be that much early, `validTo` that much late.
For accrual that pays the caller, measure from `validFrom` (`elapsedSince(t)`); for a charge the caller pays, from
`validTo` (`elapsedSinceAtMost(t)`).

## BigMap rules

- A field of the state only (`JSC0803`), with `Int` or `Bytes` values (`JSC0804`).
- Its new value is its own field transformed by `set` and `delete`, in that field of the next state:
  `{ ...state, balances: balances.set(to, v) }` (`JSC0811`, `JSC0827`). `set` and `delete` appear nowhere else.
- Never bound to a `const`, passed to a `fn`, held in an option or a list, captured by a lambda (`JSC0814`), compared,
  chosen by a condition or `match`, or used as a fold accumulator (`JSC0813`). A state whose `BigMap` is written is
  never bound, chosen or accumulated either.
- `BigMap.empty()` only as a field's value in an `init` (`JSC0810`, `JSC0817`); `m.isEmpty` ("empty before this call")
  only in a destroy (`JSC0808`).
- `Int` values are non-negative and `set(k, 0)` removes the entry; an `Int` value is stored in at most 8,192 bytes.
  `BigMap<K, Bytes>` tells absence from empty bytes. Keys of `set` and `delete` are at most 64 bytes.
- A method reads its own writes through the chain: `balances.set(caller, left)[to]`.

Every read and write is proven against the root by the shared map verifier ([MerkleMaps](/contracts/merklemaps/)).

## Libraries

A file headed `library <package>` is a **`.jsc` library** (ADR-0018 D9): imports, types, enums and fns, and no contract
(`JSC0711`). Contracts and other libraries import from it by its path relative to the importing file:

```jsc
// contracts/app/fees.jsc
jsc 2
library app

type Line = { to: Key, bps: Int }
enum Tier { Basic, Gold { since: Int } }

fn fee(amount: Int, bps: Int): Int = amount * bps / 10_000
fn rate(t: Tier): Int = match t { Basic => 100, Gold { since } => since >= 10 ? 25 : 50 }
```

```jsc
// contracts/app/Shop.jsc
jsc 2
package app

import { Line, Tier, fee, rate } from "./fees.jsc"

contract Shop {
  state { owner: Key, price: Int, lines: List<Line>, tier: Tier }
  init(price: Int, lines: List<Line>) { return { owner: caller, price, lines, tier: Basic } }
  action buy() payable {
    require(received >= price + fee(price, rate(tier)), "pay the price and the fee")
    return state
  }
}
```

| Rule | |
|---|---|
| The class | A library lowers to a JuLC `@OnchainLibrary` class of its package, named by its file: `fees.jsc` is `app.Fees` (`JSC0705` when the file name makes no class name). Its fns are `public static`, its types nested records and sealed interfaces (`Fees.Line`, `Fees.Tier`), so **Java contracts call it** as they call any on-chain library (`examples/dsl`'s `JavaShop.java`). Its generated helpers are package-private, named with `__`. A Java caller skips `.jsc`'s ingress checks: the library's fns assume a `Key` of 28 bytes, a `Hash` of 28 or 32 and canonical maps, which only `.jsc` callers guarantee, so a Java contract that builds `new Fees.Line(bytes, …)` checks those lengths itself |
| Imports | `./x.jsc` and `../dir/x.jsc`, resolved from the importing file and never outside the source folder (`JSC0706`). Only a library can be imported (`JSC0708`), and only names it declares (`JSC0708`). Libraries may import libraries, without cycles (`JSC0707`) |
| Scope | A file sees its own declarations and the names it imports; importing an enum brings its variants. A library's other declarations are not in scope (`JSC0710`), but its values flow: a fn may return a record whose type the caller did not import, and the caller reads its fields. `std` imports are per file |
| One namespace | The declarations of a build (a contract and every library it imports, transitively) share one namespace: no two of them, in any of its files, have the same name (`JSC0709`), and none takes a library's class name. No binding (a parameter, const, lambda parameter or match binding) takes a library's class name either, and two libraries of a build never share a file name, even in different packages (`JSC0709`): the generated Java names a library by its class. A method of the contract named like a library variant is refused as for its own (`JSC0203`). Known limit: two third-party libraries that declare one name cannot be combined, as there is no aliasing yet |
| Checking | A library is checked on its own, and again in each contract that imports it. The time rule (D11) runs through library calls: a library fn called with a time value is checked with that parameter marked, so a division or a `require` on it is refused at the call. An error in a library is reported at the import that brings it into the build, naming the library's own position (`JSC0712`) |
| Inputs | A library's types are checked inputs like the contract's: a `Line` in a redeemer has its `Key` checked to 28 bytes before the method runs |
| Artifacts | A library has no ABI manifest of its own: each contract's manifest states the library types its datum and redeemers reach (`"kind": "library"`, with the library's class). Each contract's IR export carries the libraries it imports (format 2), so the JavaScript reference interpreter evaluates their fns, and its message map lists a library's messages with the library's file (`"file": "fees.jsc"`) |
| Identity | A library's package and file name are its class, which importing files and Java contracts name: renaming either is a code change of every importer, and may change the scripts that use it (bloxbean/julc#328), as a contract's package does |

### Library packages and `joust.lock`

An npm package ships libraries under its `joust-lib/` folder: `.jsc` libraries, and the on-chain sources of Java
libraries (`joust-lib/<package path>/<Class>.java`). A `.jsc` file imports a package's `.jsc` library by the package
name and the path under `joust-lib/`, and a Java library by its class:

```jsc
import { fee } from "@acme/fees/fees.jsc"        // node_modules/@acme/fees/joust-lib/fees.jsc
import { cap } from "java:acme.allow.Limits"      // node_modules/<any package>/joust-lib/acme/allow/Limits.java
```

A package library's own relative imports stay inside its package (`JSC0706`). A Java library from a package is
certified like one from Gradle's `joustLibrary`, and the same codes apply. Of a package's Java sources, a build compiles
only the source closure of each library a `.jsc` file imports with `java:` or a hand-written Java contract imports; no
other package source reaches the build. Links under `joust-lib/` are not followed, and two packages that ship one Java
path are refused.

**`joust.lock`** (committed at the project's root) pins every library that comes from **outside the project's sources**
by the SHA-256 of its on-chain sources: a package's `.jsc` library (with the libraries it imports), or a Java library's
source closure (every source file its class's file names, transitively; keyed by its path inside `joust-lib/`), whether
a `.jsc` file imports it with `java:` or a hand-written Java contract imports it (ADR-0018 J12). `joust build` lists every library it used with its hash. It fails with `JSC0731` when
such a library is not pinned, and with `JSC0732` when its sources differ from the pin. Review the library, then run
`joust build --accept-lock`, which writes the lock to commit. The project's own `.jsc` libraries are part of its sources
and are not pinned. On Gradle, `generateJsc` checks `joust.lock` for the `joustLibrary` libraries, and `acceptJoustLock`
writes it.

```json
{ "lock": 1, "libraries": { "@acme/fees/fees.jsc": "…64 hex…", "java:acme.allow.Limits": "…64 hex…" } }
```

## Java libraries (`java:`)

A `.jsc` file may import the public static methods and records of a Java (JuLC) on-chain library whose **on-chain
sources** are on the library path and **certified** (ADR-0018 D9, M4b):

```jsc
import { Entry, isAllowed, limitOf, entry } from "java:org.example.compliance.AllowList"
```

On Gradle, the library's jar goes in the `joustLibrary` configuration, as sources only:

```groovy
dependencies {
    joustLibrary 'org.example:compliance:1.0'   // its META-INF/plutus-sources
}
```

The build extracts the library's `META-INF/plutus-sources`, compiles them into the project (the JVM side runs these
sources, never the jar's classes), and certifies them before any import is admitted. Certification covers:

- each signature's exact Java types, mapped to `.jsc` or refused;
- every reachable body, checked with `SubsetLint`;
- no casts and no reference equality;
- only calls into the trusted base (D8's table, JOUST's `Require` and adapters, an allow-list of `BigInteger`, `JulcList`,
  `JulcMap` and `Optional` operations);
- none of the catalogue of known JVM/on-chain differences.

`checkJoustLibraries` fails when a library class also reaches the runtime class path from a jar. When a contract is
loaded, the runtime checks the bytes of each library class against the build's.

| Rule | Code |
|---|---|
| No sources of the class on the library path | `JSC0720` |
| The library is not certified (each problem, with its file and line) | `JSC0721` |
| A fn whose signature does not map (`PlutusData`, maps, values, `void`, generics, fixed-width numbers) | `JSC0722` |
| An overloaded name | `JSC0723` |
| A Java record is read-only: built by the library's fns, never by an object literal | `JSC0724` |
| An opaque record (a field that does not map) is never written as a type, read or compared | `JSC0725` |
| A time value never reaches a Java fn (D11) | `JSC0726` |
| A library class also on the runtime class path (Gradle) | `JSC0727` |

`byte[]` maps to `Bytes` (a Java signature cannot say `Key`): make a `Key` of a result with `asKey(b)`. The reference
interpreters do not evaluate a Java library's body: a call that reaches one has no answer there, and such calls are
differential-tested on the JVM, the transition program and the validator, beside the library's own per-function vectors.
The details, and the catalogue, are in
[jsc-2-java-libraries.md](https://github.com/bloxbean/joust/blob/main/docs/reference/jsc-2-java-libraries.md).

## The ABI manifest

For every `.jsc` 2 contract the lowering writes `<Contract>.abi.json` (format `"abi": 2`), which the project commits
beside the `.jsc` file:

| Key | Content |
|---|---|
| `contract`, `source` | the qualified contract name and the `.jsc` file |
| `datum` | the `State` constructor, its fields in order, each with its `.jsc` type and data shape |
| `redeemers.spend` | one constructor per action, then per destroy, in source order, with its index and fields (the generated `ctx` included) |
| `redeemers.mint` | `CreateInstance` (`seed`, `ctx`) and `BurnInstance` |
| `types` | every schema the datum and the redeemers reach: records, enums, imported library types (`"kind": "library"`, with the library's class), and API and ledger types such as `Ctx`, `TxOutRef`, `MerkleMap` |
| `timeFields` | the state's time fields |

Views are not encoded, so moving or adding a view does not change the manifest.

**The gate.** Every build compares the lowering's manifest with the committed one. Equal passes. A missing manifest
fails with `JSC0003`; a different one with `JSC0002`, naming the first line that differs; and Java lowered from a file
whose manifest is refused is not written. The only ways to accept a new or changed manifest are explicit:

| Path | Accept |
|---|---|
| npm | `joust build --accept-abi`, `joust dev --accept-abi` |
| Gradle (plugin `org.julclang.joust`) | `./gradlew acceptJscAbi` |
| JVM | `JscMain <srcDir> <outDir> --accept-abi` |

No Gradle property, system property or `gradle.properties` line switches the gate off. Review the diff and commit
the manifest: a change means a deployed instance's datum or redeemers would be read differently, so the new contract
must be deployed as a new script.

**The cross-check.** Each manifest is also compared, structurally, with the processor's description of the same
contract (constructor indices, field names and order, data shapes, every reachable schema): at every npm build, and on
Gradle in `checkJscAbi`, after `compileJava`, as part of `check`. A difference is `JSC0004`, an internal error of the
lowering; please report it.

## Diagnostics

Every error and warning has a stable code and a position, on both build paths. Gradle (`JscMain`) prints, with the
file relative to `src/main/jsc`:

```text
Ledger.jsc:34:13: error[JSC0502]: a time value cannot decide here: compare times only with after(t) or before(t) in a require (ADR-0018 D11)
Ledger.jsc:72:3: warning[JSC9001]: settle never reads balance; a destroy must pay out everything the instance holds
```

`joust build` prints the same fields in the order `error[JSC0502]: <file>:<line>:<col>: <message>`, the file relative to
the contracts folder.

A code names one rule and is never reused; a message may change wording, its code does not. The full list, checked
against the sources by a test, is the
[diagnostics catalogue](https://github.com/bloxbean/joust/blob/main/docs/reference/jsc-2-diagnostics.md). The ranges:

| Codes | Area |
|---|---|
| `JSC0001`–`JSC0004` | files and the ABI manifest |
| `JSC01xx` | syntax and JavaScript habits |
| `JSC02xx` | names and declarations |
| `JSC03xx` | types and expressions |
| `JSC04xx` | methods, modifiers, effects |
| `JSC05xx` | time (D11) |
| `JSC06xx` | recursion |
| `JSC07xx` | imports |
| `JSC08xx` | maps |
| `JSC09xx` | enums and `match` |
| `JSC10xx` | lists, loops and lambdas |
| `JSC11xx` | `joust migrate` refusals |
| `JSC9xxx` | warnings |

`JSC9006` is the warning every build of a v1 file prints: v1 is deprecated, and
[`joust migrate`](/languages/jsc-migration/) translates the file.

A diagnostic of javac or the JOUST processor on generated Java is reported at the `.jsc` line and column the source
map gives, with the generated file and line as a note.

## Running the lowering

| Entry point | Use |
|---|---|
| `org.julclang.state.dsl.JscMain <srcDir> <outDir> [--accept-abi]` | Lowers every `.jsc` under `srcDir` into `outDir` (emptied first), with each `.jsc` 2 file's source map; checks (or with `--accept-abi` writes) the ABI manifests. A file's `./x.jsc` imports resolve to other files of `srcDir`. Exits 1 on an error, 2 on bad usage. Gradle's `generateJsc` and `acceptJscAbi` run it |
| `JscMain --check-abi <srcDir> <descriptionsDir>` | Checks every manifest against the processor's descriptions (`checkJscAbi`) |
| `JscMain --migrate <srcDir> <outDir> [--in-place]` | Translates v1 files to `.jsc` 2 ([migration](/languages/jsc-migration/)) |
| `JscMain.lowerWithWarnings(source, fileName)` | `Lowered(java, diagnostics, fileName, sourceMapJson, abiJson)` for one file, on its own (it imports no libraries) |
| `JscMain.lowerWithWarnings(source, fileName, id, modules)` | The same for the file `id` of a build whose libraries `modules` (`JscModules.of(files)`) finds |
| `Toolchain.build(files, options)` (`julc-state-toolchain`) | Lowers `.jsc` entries, then compiles everything as Gradle does; used by `joust build` |

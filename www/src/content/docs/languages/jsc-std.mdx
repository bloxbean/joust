A `.jsc` 2 contract calls three kinds of functions: the **prelude** (always in scope), the **`std` modules** (imported
by name), and its own `fn`s. List and map methods (`xs.fold`, `m.get`) are on the
[language reference](/languages/jsc-reference/#lists-maps-and-options).

```jsc
import { blake2b_224 } from "std/crypto"
import { slice, length } from "std/bytes"
```

An import names functions of one module. A function used without its import is an error (`JSC0704`, which names the
module to import it from); a name imported from the wrong module is `JSC0702`; a `fn` with an imported name is
`JSC0703`.

<Aside type="note" title="A preview">
`.jsc` 2 is a preview ([ADR-0018](https://github.com/bloxbean/joust/blob/main/docs/adr/0018-jsc-2-immutable-contract-language.md)).
`std/value` and `std/address` come with `Value` and `Address` in milestone M2; importing them now is `JSC0304`.
</Aside>

## How a row is bound

Each `std` function is a row of a binding table
([`Std.java`](https://github.com/bloxbean/joust/blob/main/julc-state-dsl/src/main/java/org/julclang/state/dsl/v2/Std.java),
ADR-0018 D8): a `.jsc` signature, a Java target, a conversion policy and a domain. The generated Java calls the target,
so the same function runs on the JVM and, compiled by JuLC, on chain.

| Policy | Meaning |
|---|---|
| direct | Every argument and the result have the same Java type on both sides (`byte[]`, `boolean`, `BigInteger`) |
| long result | The target returns a `long`, which goes straight into `BigInteger.valueOf`; no `Int` argument is narrowed |
| adapter | The target is a JOUST API adapter (`BytesAdapter`, `MathAdapter`, `BitsAdapter`, `CryptoAdapter` in `julc-state-api`) that takes `BigInteger`s, checks the domain with a `require` on both sides, then narrows and calls JuLC's stdlib |
| generated | No library target: the lowering generates the code, and the reference interpreter implements it independently |

**Domain:** the arguments a function accepts. Outside it the call fails, on the JVM before anything is submitted and on
chain alike. **A time value as an argument:** whether a value that depends on `validFrom` or `validTo` may reach the
function. Only functions that are total and whose cost does not depend on the window accept one
([the time rule](/languages/jsc-reference/#time-d11)); passing a time value to any other is an error at the call
(`JSC0509`).

A test (`JscV2BindingTest` in `julc-state-toolchain`) resolves every row's Java target with javac and compares it with
the table, so a JuLC upgrade that renames or retypes a function fails JOUST's build, never your contract. The tables
below are generated from the same table and checked by `JscV2StdDocTest`.

## The prelude

No import needed.

| Function | Signature | Meaning |
|---|---|---|
| `min`, `max` | `min(Int, Int): Int` | The smaller or larger of two `Int`s |
| `abs` | `abs(Int): Int` | The absolute value |
| `utf8` | `utf8("text"): Bytes` | The UTF-8 bytes of a string literal (the only place a string is a value) |
| `asKey` | `asKey(Bytes): Key` | A checked conversion to a 28-byte key hash: a literal is checked when the file compiles (`JSC0323`), any other value at run time. A time value cannot reach it (`JSC0507`) |
| `asHash` | `asHash(Bytes): Hash` | The same, to a 28-byte script hash or policy id |
| `range` | `range(a, b)` | The `Int`s from `a` up to `b`, exclusive; empty when `b <= a`. Only the receiver of `any`, `all`, `fold`, `filter` or `map`, or the list of a `for` loop: no list is built (`JSC1009`). A bound cannot be a time value (`JSC0516`) |
| `Some` | `Some(x): Option<T>` | A present `Option`; `None` is the absent one. `Some(None)` is refused (`JSC0322`) |
| `after`, `before` | `after(Int): Bool` | The whole validity window is after (before) the time. Only at the top of a `require`, alone or under `&&` or `\|\|` ([time](/languages/jsc-reference/#time-d11)). Also importable from `std/time` |

## The modules

`std/list` functions are generic: `T` is the element type of the list they get, and `indexOf` compares with the
structural equality of `==`.

## Not bound

- `keccak_256`, ECDSA and Schnorr signatures, RIPEMD-160: the JVM's crypto provider lacks them, and a function is
  bound only when every runtime fails exactly where the ledger's builtin fails (ADR-0018 D8, F18).
- `integerToByteString` and `writeBits`: their domains need checks `.jsc` 2 does not have yet.
- Functions over raw `PlutusData`, and JuLC's transaction libraries (`ContextsLib`, `OutputLib`): the processor owns
  the transaction checks.

For anything else, write the contract, or that part of it, in [Java](/languages/java/).

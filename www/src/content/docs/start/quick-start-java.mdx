This page takes you from the `joust` command to a contract running on a local Cardano network, with Java 25 and
Gradle. You create a project with `joust new`, build and test it, and run it on Yaci DevKit. Then you look at each
file it wrote.

If you would rather use Node and no JDK, see [Quick start: JavaScript & TypeScript](/start/quick-start-npm/).

<Aside type="caution" title="Experimental, pre-release">

JOUST is a research and learning project: do not use it in production. Releases come often: the newest is the newest
entry on the [releases page](https://github.com/bloxbean/joust/releases) whose tag starts with `v`.

</Aside>

## Before you start

[Install JOUST](/start/install/) covers each of these.

- **`joust`**: `brew install bloxbean/tap/joust`, or the archive for your platform from the
  [releases page](https://github.com/bloxbean/joust/releases). Check it with `joust version`.
- **JDK 25.** You do not need Gradle: the project comes with the Gradle wrapper.
- **Node.js 22 or newer**, for Yaci DevKit's npm package and for the playground.
- **Yaci DevKit** for the last step: `npm install -g @bloxbean/yaci-devkit` once, then
  `yaci-devkit up --enable-yaci-store` in a terminal of its own. It is a private Cardano network on your machine: its
  faucet hands out test ADA, so nothing costs real money.

## Create, build and run

<Steps>

1. **Create the project.**

   <Tabs syncKey="lang">
   <TabItem label="Java">

   ```sh
   joust new my-counter                  # -p org.example for your own package (default: app)
   cd my-counter
   ```

   </TabItem>
   <TabItem label=".jsc">

   ```sh
   joust new my-counter -l jsc           # the contract in .jsc, a language preview
   cd my-counter
   ```

   </TabItem>
   </Tabs>

   ```text
   Created /path/to/my-counter (Gradle, java, JOUST <version>)

     cd my-counter
     ./gradlew build     # the validator, the client, the description; and the tests
     ./gradlew run       # the counter on Yaci DevKit: yaci-devkit up --enable-yaci-store
   ```

   The directory must be new or empty. It holds a `Counter` contract, its tests, a small app that runs it on DevKit,
   and the Gradle wrapper ([what it wrote](#what-joust-new-wrote)).

2. **Check the JOUST version.** It is the version on the plugin line of `build.gradle`:

   ```groovy title="build.gradle"
   plugins {
       id 'application'
       // JOUST <version>: the JOUST and JuLC processors, the on-chain sources, .jsc, test settings.
       // Upgrading JOUST is this version.
       id 'org.julclang.joust' version '<version>'
   }
   ```

   `joust new` writes the version of the `joust` that ran it. Compare it with the newest release on the
   [releases page](https://github.com/bloxbean/joust/releases) (the newest tag starting with `v`, not the "Development
   snapshot" entry). If yours is older, change the version here, and `brew upgrade joust` for your next project. The
   plugin brings matching JuLC and cardano-client-lib versions with it, so this is the only version to keep up to date.

3. **Build.**

   ```sh
   ./gradlew build                       # or: joust build
   ```

   The first build downloads the plugin, JuLC and cardano-client-lib. It compiles the contract, generates its
   validator and client, compiles the validator to UPLC, and runs the tests:

   | Output | Where | What it is |
   |---|---|---|
   | `CounterValidator.java` | `build/generated/sources/annotationProcessor/java/main/app/` | The on-chain validator source (MINT + SPEND) |
   | `CounterClient.java` | same | The typed client: `deploy`, `at`, `increment`, `reset`, `close`, `count`, `state` |
   | `CounterValidator.plutus.json` | `build/classes/java/main/META-INF/plutus/` | The compiled UPLC script; the runtime and the testkit load it from the classpath |
   | `app.Counter.json` | `build/classes/java/main/META-INF/joust/` | The description (CIP-57 plus `x-joust`) JavaScript clients are generated from |

   Read the generated sources: they are ordinary Java, and every check the validator makes is visible in
   `CounterValidator.java`. If your contract breaks a rule (an `int` in a method, two `@Init` methods, a `@Payable`
   without `Ctx`), the build fails with a compiler error on the offending line; see [Java](/languages/java/).

4. **Test.**

   ```sh
   ./gradlew test                        # or: joust test
   ```

   `build` already ran them; this runs only the tests.

   `CounterTest` runs the contract's methods as plain Java, then evaluates the compiled validator against
   transactions shaped like the runtime's, and runs the attack suite on each accepted one.

5. **Run it on DevKit.** Start DevKit in another terminal if it is not running
   (`yaci-devkit up --enable-yaci-store`, and leave it running), then:

   ```sh
   ./gradlew run                         # or: joust run
   ```

   `CounterMain` funds two fresh accounts from the DevKit faucet, deploys a counter as Alice, increments it as Bob and
   Alice, shows Bob's reset being refused before anything is submitted, and closes the counter (hashes shortened):

   ```text
     [joust] deploy Counter: submitted 34ba07cb…
   deployed instance d11c40ff…
     [joust] Counter.increment: submitted 85ec809e…
     [joust] Counter.increment: submitted c1733515…
   count = 7
   refused before submitting: Counter.reset: must be called by the key in 'owner'
     [joust] Counter.close: submitted c4419d0b…
   closed in c4419d0b…
   ```

   Your hashes will differ. The first run on a fresh DevKit also logs `publish the Counter reference script: submitted
   ...` and `published the Counter reference script in ...`: the first deploy of a contract on a network publishes its
   script once, for every later transaction to read.
   Paste a transaction hash from the output into Yaci Viewer (`http://localhost:5173`) to see the state UTxO and its
   datum.

</Steps>

## What `joust new` wrote

<FileTree>

- my-counter/
  - settings.gradle where the plugin comes from
  - build.gradle the plugin, with the JOUST version
  - gradle.properties
  - gradlew the Gradle wrapper, with gradle/wrapper/
  - README.md
  - src/
    - main/
      - java/app/
        - Counter.java the contract (with -l jsc: src/main/jsc/app/Counter.jsc and Counter.abi.json)
        - CounterMain.java the DevKit app
        - Devnet.java the DevKit connection
    - test/java/app/
      - CounterTest.java

</FileTree>

The plugin `org.julclang.joust` does the JOUST setup: the processors, the on-chain sources, the runtime and the
testkit, at versions that match. [Gradle builds](/apps/gradle-builds/) lists what it adds, and how to set up a build
by hand instead.

### The contract

<Tabs syncKey="lang">
<TabItem label="Java">

```java title="src/main/java/app/Counter.java"
package app;

import org.julclang.core.types.JulcList;
import org.julclang.state.api.Action;
import org.julclang.state.api.Ctx;
import org.julclang.state.api.Destroy;
import org.julclang.state.api.Init;
import org.julclang.state.api.OnlyOwner;
import org.julclang.state.api.Payout;
import org.julclang.state.api.Payouts;
import org.julclang.state.api.Require;
import org.julclang.state.api.StateContract;
import org.julclang.state.api.View;

import java.math.BigInteger;

@StateContract(maxDatumBytes = 128)
public class Counter {

    public record State(BigInteger count, byte[] owner) {}

    @Init
    public static State init(Ctx ctx) {
        return new State(BigInteger.ZERO, ctx.caller());
    }

    @Action
    public static State increment(State s, BigInteger by) {
        Require.that(by.compareTo(BigInteger.ZERO) > 0, "increment must be positive");
        return new State(s.count().add(by), s.owner());
    }

    @Action
    @OnlyOwner
    public static State reset(State s) {
        return new State(BigInteger.ZERO, s.owner());
    }

    @Destroy
    @OnlyOwner
    public static JulcList<Payout> close(State s, Ctx ctx) {
        return Payouts.of(s.owner(), ctx.balance());
    }

    @View
    public static BigInteger count(State s) {
        return s.count();
    }
}
```

</TabItem>
<TabItem label=".jsc">

```jsc title="src/main/jsc/app/Counter.jsc"
jsc 1
package app

contract Counter(maxDatumBytes = 128) {
  state { count: Int, owner: Key }

  init() {
    return { count: 0, owner: caller }
  }

  action increment(by: Int) {
    require(by > 0, "increment must be positive")
    return { ...state, count: count + by }
  }

  action reset() only owner {
    return { ...state, count: 0 }
  }

  destroy close() only owner {
    pay(owner, balance)
  }

  view count(): Int = count
}
```

The build lowers it to the Java contract on the other tab (into `build/generated/sources/jsc`) and compiles that.
`Counter.abi.json` beside it records how the state and the calls are encoded on chain: the build fails when that
changes, until you accept it with `./gradlew acceptJscAbi` and commit the new manifest. `.jsc` is a language preview:
a later JOUST may compile the same file to a different script hash, so use it on DevKit and testnets, not to hold
value. See [.jsc](/languages/jsc/).

</TabItem>
</Tabs>

This is the [counter example](https://github.com/bloxbean/joust/blob/main/examples/counter/src/main/java/org/julclang/state/examples/counter/Counter.java)
in package `app`. [Your first contract](/start/first-contract/) explains every line.

### The test

`julc-state-testkit` gives you `StateHarness`, which evaluates the compiled validator against transactions shaped
like the ones the runtime builds, and `Attacks`, which mutates each accepted transaction in every way the
invariants forbid:

```java title="src/test/java/app/CounterTest.java"
package app;

import org.julclang.state.api.Ctx;
import org.julclang.state.api.RequireException;
import org.julclang.state.testkit.Attacks;
import org.julclang.state.testkit.StateHarness;
import org.junit.jupiter.api.Test;

import java.math.BigInteger;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;

class CounterTest {

    static final byte[] ALICE = StateHarness.fill(28, 0x11);
    static final byte[] BOB = StateHarness.fill(28, 0x22);

    final StateHarness<Counter.State> h = StateHarness.of(CounterClient.SPEC);

    @Test
    void plainJava() {
        var s0 = Counter.init(h.ctx(ALICE, BigInteger.ZERO, BigInteger.ZERO));
        var s1 = Counter.increment(s0, BigInteger.valueOf(5));
        assertEquals(BigInteger.valueOf(5), Counter.count(s1));
        var e = assertThrows(RequireException.class, () -> Counter.increment(s1, BigInteger.ZERO));
        assertEquals("increment must be positive", e.getMessage());
    }

    @Test
    void incrementOnChain() {
        var live = h.live(new Counter.State(BigInteger.valueOf(3), ALICE), BigInteger.ZERO);
        var next = Counter.increment(live.state(), BigInteger.TEN);
        var tx = h.act(live, new CounterValidator.Increment(BigInteger.TEN), next, null, null);
        System.out.println(h.assertAccepted(tx));
        Attacks.assertAllRejected(h, tx);
    }

    @Test
    void resetByStrangerRejectedOnChain() {
        var live = h.live(new Counter.State(BigInteger.valueOf(42), ALICE), BigInteger.ZERO);
        h.assertRejected(h.act(live, new CounterValidator.Reset(), Counter.reset(live.state()), BOB, null), "@OnlyOwner");
    }
}
```

The examples' [`CounterTest`](https://github.com/bloxbean/joust/blob/main/examples/counter/src/test/java/org/julclang/state/examples/counter/CounterTest.java)
covers every call, including the create and the close; [Testing](/contracts/testing/) explains the harness.

### The DevKit app

`CounterMain` is the app `./gradlew run` starts. It calls the generated `CounterClient`:

```java title="src/main/java/app/CounterMain.java"
package app;

import org.julclang.state.api.RequireException;

import java.math.BigInteger;

public class CounterMain {
    public static void main(String[] args) throws Exception {
        var runtime = Devnet.runtime();
        var alice = Devnet.fundedAccount(500);
        var bob = Devnet.fundedAccount(500);

        CounterClient counter = CounterClient.deploy(runtime, alice);
        System.out.println("deployed instance " + counter.instanceId());

        counter.increment(bob, BigInteger.valueOf(5));
        counter.increment(alice, BigInteger.TWO);
        System.out.println("count = " + counter.count());               // 7

        try {
            counter.reset(bob);                                         // not the owner
        } catch (RequireException e) {
            System.out.println("refused before submitting: " + e.getMessage());
        }

        var closed = counter.close(alice);                              // the deposit goes back to alice
        System.out.println("closed in " + closed.txHash());
    }
}
```

The runtime needs a `StateRuntime`: a chain backend, the network's slot clock, and a few options. `Devnet` makes one
for DevKit; it is a trimmed copy of the examples' helper,
[`examples/devkit/.../DevKit.java`](https://github.com/bloxbean/joust/blob/main/examples/devkit/src/main/java/org/julclang/state/examples/devkit/DevKit.java):

```java title="src/main/java/app/Devnet.java"
package app;

import com.bloxbean.cardano.client.account.Account;
import com.bloxbean.cardano.client.backend.api.BackendService;
import com.bloxbean.cardano.client.backend.api.DefaultProtocolParamsSupplier;
import com.bloxbean.cardano.client.backend.api.DefaultScriptSupplier;
import com.bloxbean.cardano.client.backend.api.DefaultUtxoSupplier;
import com.bloxbean.cardano.client.backend.blockfrost.service.BFBackendService;
import com.bloxbean.cardano.client.common.model.Networks;
import org.julclang.clientlib.eval.JulcTransactionEvaluator;
import org.julclang.clientlib.eval.SlotConfig;
import org.julclang.state.runtime.SlotChainTime;
import org.julclang.state.runtime.StateRuntime;

import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;
import java.util.regex.Pattern;

/** Yaci DevKit: Yaci Store on :8080, the admin API on :10000. Adapted from the examples' DevKit helper. */
final class Devnet {
    static final String STORE = "http://localhost:8080/api/v1/";
    static final String ADMIN = "http://localhost:10000";
    static final HttpClient HTTP = HttpClient.newHttpClient();

    static StateRuntime runtime() throws Exception {
        BackendService backend = new BFBackendService(STORE, "dummy-key");
        // The DevKit's slot clock, from its genesis.
        String genesis = get(ADMIN + "/local-cluster/api/admin/devnet");
        long startSec = Long.parseLong(find(genesis, "startTime", "-?\\d+"));
        double slotSec = Double.parseDouble(find(genesis, "slotLength", "[\\d.]+"));
        SlotChainTime time = new SlotChainTime(0, startSec * 1000, Math.round(slotSec * 1000), backend);
        return StateRuntime.builder(backend)
                .network(Networks.testnet())
                .chainTime(time)
                .ttl(Duration.ofSeconds(20))      // DevKit's time horizon is minutes: keep the validity window short
                .evaluator(new JulcTransactionEvaluator(   // script budgets computed locally by JuLC
                        new DefaultUtxoSupplier(backend.getUtxoService()),
                        new DefaultProtocolParamsSupplier(backend.getEpochService()),
                        new DefaultScriptSupplier(backend.getScriptService()),
                        new SlotConfig(time.zeroSlot(), time.zeroTimeMs(), time.slotLengthMs())))
                .log(msg -> System.out.println("  [joust] " + msg))
                .build();
    }

    /** A fresh account with {@code ada} ADA from the DevKit faucet. */
    static Account fundedAccount(long ada) throws Exception {
        var account = new Account(Networks.testnet());
        HTTP.send(HttpRequest.newBuilder(URI.create(ADMIN + "/local-cluster/api/addresses/topup"))
                .header("Content-Type", "application/json")
                .POST(HttpRequest.BodyPublishers.ofString(
                        "{\"address\":\"" + account.baseAddress() + "\",\"adaAmount\":" + ada + "}"))
                .build(), HttpResponse.BodyHandlers.ofString());
        Thread.sleep(2000);   // let Yaci Store index the top-up
        return account;
    }

    private static String get(String url) throws Exception {
        return HTTP.send(HttpRequest.newBuilder(URI.create(url)).GET().build(), HttpResponse.BodyHandlers.ofString()).body();
    }

    private static String find(String json, String key, String valuePattern) {
        var m = Pattern.compile("\"" + key + "\"\\s*:\\s*(" + valuePattern + ")").matcher(json);
        if (!m.find()) throw new IllegalArgumentException("key not found: " + key);
        return m.group(1);
    }
}
```

## Try it in the playground

<Aside type="caution" title="Experimental">
The playground runs on JOUST's npm packages and their WebAssembly engine, even for a Gradle project.
</Aside>

The playground is a page in your browser where you call your contract without writing any code: pick who signs, fill
in a form, review the transaction, approve. It needs Node.js 22 or newer, and runs offline (no DevKit) by default.

```sh
joust playground
```

The first run installs the playground once into `~/.joust/playground/<version>` (with npm), then runs
`./gradlew build joustHostSpec` and opens the page. If it refuses because other accounts could change your build, it
prints the `chmod go-w` command that fixes it.

<Steps>

1. Click `Counter` under **Contracts**. Its operations appear as cards: `init`, `increment`, `reset` and `close`.
2. Click **Review…** on `init`. The first call publishes the contract's script, so you approve a **Review publication**
   dialog first, then the call's own. Click **Approve and sign as Alice** in each. The new counter appears under
   **Instances**.
3. Type `5` into `by` on the `increment` card, click **Review…** and approve. The state shows the count 5.
4. Choose Bob under **Identities** and click **Review…** on `reset`. Bob is not the owner, so it is refused before
   anything is signed.

</Steps>

**Ctrl-C** in the terminal stops it. `--mode devkit` runs the same page against a running Yaci DevKit.
[The playground](/apps/playground/) explains everything on the page.

## Explore the examples

The JOUST repository has one tested example per feature: vaults, escrows, tokens in MerkleMaps, banks, pools, a DEX
and more. To run them, clone it (no `joust` needed; the checkout has its own Gradle wrapper):

```sh
git clone https://github.com/bloxbean/joust.git
cd joust
./gradlew :examples:counter:test          # JVM, harness and attack-suite tests; the DevKit test if DevKit is up
./gradlew :examples:vault:run             # an example's app on DevKit
```

The checkout builds against its own modules, so it is the code on `main`, which may be ahead of the newest release.
See [Examples](/reference/examples/).

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `joust: command not found` | Install it ([Install JOUST](/start/install/)), or put the unpacked archive's `joust` on your `PATH` |
| `No matching toolchains found ... languageVersion=25` | The project needs a Java 25 toolchain: install JDK 25 |
| `Plugin [id: 'org.julclang.joust', version: '...'] was not found` | The plugin version in `build.gradle` is not a JOUST release: compare it with the [releases page](https://github.com/bloxbean/joust/releases) |
| `Could not find org.julclang:julc-...` | A repository is missing from the build. For a hand-written build, see [Gradle builds](/apps/gradle-builds/#troubleshooting) |
| `'int' in a @StateContract ... Use BigInteger` | `SubsetLint`: contract code computes in `BigInteger` only. See [Java](/languages/java/) |
| Connection refused on `localhost:8080` or `:10000` | DevKit is not running: `yaci-devkit up --enable-yaci-store` |
| `PastHorizon` from the node | The validity window reaches beyond what the network can convert to time. Keep `ttl` short on DevKit (20 s in `Devnet`) |

More in [Troubleshooting](/reference/troubleshooting/).

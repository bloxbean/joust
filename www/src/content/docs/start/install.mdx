Everything starts from one command, `joust`. It creates a project for the path you choose, and inside a project it
runs that project's build. This page installs it, with the few tools your path needs, and shows how to check which
JOUST version you are on.

<Aside type="caution" title="Experimental, pre-release">

JOUST is a research and learning project: do not use it in production. Releases come often. The newest one is the
newest entry on the [releases page](https://github.com/bloxbean/joust/releases) whose tag starts with `v` (not the
"Development snapshot" entry). Check there before you start, and when something you read here does not match what
you see.

</Aside>

## Pick your path

| You want to | Contract in | App in | You need | Status |
|---|---|---|---|---|
| Build a Cardano app on the JVM | Java | Java, on cardano-client-lib | JDK 25 (Gradle comes with the project) | Supported |
| Try JOUST's compact contract syntax | [`.jsc`](/languages/jsc/) | Java | JDK 25 | Language preview |
| Build a Node script or a browser dApp | `.jsc` or Java | JavaScript or TypeScript | Node 22 or newer (no JDK) | Experimental |

You can change your mind later: a contract compiles to the same validator and the same description from either side.

## Install

<Steps>

1. **Install `joust`.**

   <Tabs>
   <TabItem label="Homebrew">

   ```sh
   brew install bloxbean/tap/joust
   ```

   For Apple silicon Macs and Linux (x86_64, arm64). There is no native `joust` for Intel Macs: use the npm path there.

   </TabItem>
   <TabItem label="Release archive">

   Download `joust-<version>-<platform>.zip` for your platform (`<platform>` is `macos-aarch64`, `linux-x86_64` or
   `linux-arm64`) from the newest release on the [releases page](https://github.com/bloxbean/joust/releases). Check it,
   then unpack it and put `joust` on your `PATH`:

   ```sh
   shasum -a 256 -c joust-<version>-SHA256SUMS.txt --ignore-missing
   gh attestation verify joust-<version>-<platform>.zip -R bloxbean/joust
   ```

   On macOS, also clear the quarantine flag, since the binary is not notarised: `xattr -d com.apple.quarantine joust`.

   </TabItem>
   <TabItem label="npm only">

   On the npm path you do not need the native `joust`: `npm create joust@latest` creates a project, and the project's
   own `@julclang/joust` gives you `npx joust` and the `npm run` scripts. See
   [Quick start: JavaScript & TypeScript](/start/quick-start-npm/).

   Do not also install `@julclang/joust` globally next to the native `joust`: with Homebrew's Node both use one path.
   Keep the native one global and `@julclang/joust` per project.

   </TabItem>
   </Tabs>

   The native `joust` is a single binary: it needs neither a JDK nor Node to run.

2. **Check it.**

   ```sh
   joust version          # joust <version> (native)
   ```

   On the npm path, run `npx joust version` inside a project instead.

   Compare `<version>` with the newest release on the [releases page](https://github.com/bloxbean/joust/releases).
   `joust new` writes the version of the `joust` that runs it into the project, so upgrade before you create a
   project (`brew upgrade joust`, or a newer archive).

3. **Install what your path needs.**

   - **Gradle (Java or `.jsc`):** JDK 25. You do not need Gradle: `joust new` writes the Gradle wrapper (`./gradlew`)
     into the project.
   - **npm (JavaScript):** Node 22 or newer. The playground (`joust playground`) needs Node 22 too, on
     both paths.

4. **Start a local Cardano network.** The quick starts run on [Yaci DevKit](https://github.com/bloxbean/yaci-devkit),
   started with its indexer, Yaci Store:

   ```sh
   yaci-devkit up --enable-yaci-store
   ```

   Yaci Store then answers on `http://localhost:8080` (a Blockfrost-compatible API), the DevKit admin API on
   `http://localhost:10000` (slot clock, faucet), and the Yaci Viewer explorer on `http://localhost:5173`. See
   [Networks and chain providers](/apps/networks-and-providers/).

</Steps>

## Which JOUST version a project uses

A project pins its JOUST version in one place. Upgrading JOUST means changing that version, after checking the
[releases page](https://github.com/bloxbean/joust/releases) for the newest one.

<Tabs syncKey="lang">
<TabItem label="Java">

```groovy title="build.gradle"
plugins {
    id 'application'
    id 'org.julclang.joust' version '<version>'    // the JOUST release
}
```

The Gradle plugin brings every other version (JuLC, cardano-client-lib) from the JOUST release it belongs to, so
they always match. See [Gradle builds](/apps/gradle-builds/).

</TabItem>
<TabItem label=".jsc">

The same `build.gradle` line as for Java: a `.jsc` project on Gradle is a Java project with its contract in
`src/main/jsc/`.

</TabItem>
<TabItem label="JavaScript">

```json title="package.json (dependencies)"
"@julclang/joust": "<version>",
"@julclang/joust-runtime": "<version>",
"@julclang/state-client": "<version>"
```

All three are released together, at the same version. `npx joust version` prints the one the project uses, and
`npm view @julclang/joust version` the newest on npm.

</TabItem>
</Tabs>

JOUST is **pre-release**. Every feature on this page is implemented, tested at three levels (the method on the JVM,
the compiled validator in a harness with the attack suite, and end to end on Yaci DevKit) and recorded in an
[architecture decision](/project/architecture-decisions/). Nothing has a stable release yet: APIs can still change.

<Aside type="caution" title="Not published yet">
Maven snapshots are in the BloxBean snapshot repository (`https://repo.bloxbean.org/maven/snapshots`, version
`0.1.0-pre1-<sha7>-SNAPSHOT`), but they need a JuLC build that is not published: build it into mavenLocal with
`.github/ci/build-julc.sh` from a JOUST checkout. The npm packages (`@julclang/joust`, `@julclang/joust-runtime`,
`@julclang/state-client`, `create-joust`) are **not on npmjs.org**: install them from a local registry
(`bash js/publish-local.sh`, see [Quick start: npm](/start/quick-start-npm/)).
</Aside>

## What works today

### Contracts

| Option | What it gives you | ADR | Example |
|---|---|---|---|
| A | Single-UTxO state machines: `@Init`, `@Action`, `@View`, `@Destroy`, `@Payable`, `@SignedBy`/`@OnlyOwner`, `@ValidAfter`/`@ValidBefore`, payouts | 0001 | `counter`, `vault`, `escrow`, `crowdfund` |
| B | `MerkleMap` state: unbounded maps in a 32-byte root, proofs checked by the shared `MapVerifier` | 0002, 0014 | `token`, `locker` |
| C | `@Owned` objects beside shared state: contention-free per-user UTxOs | 0003 | `bank` |
| D | `@Batched` intents and a permissionless batcher for hot shared state | 0004 | `pool` |
| E | `.jsc`, a compact contract language lowered to a Java `@StateContract` | 0005 | `dsl` |
| F | Optimistic L2 **spike**: checkpoints, a challenge window, one-step fraud proofs | 0006 | `rollup` |
| G | Native assets in state, minting under the contract's policy, general outputs (`Send`) | 0007 | `dex`, `market` |
| H | Cheaper generated checks and smaller scripts | 0008 | all |
| I | `@Params`, `@Quorum`, `@AuthorizedBy` (keys and script governors), `@Invariant`, authenticated events | 0009 | `treasury` |
| J | Every script purpose: `@Withdraw`, `@Certify`, `@Votes`, `@Propose`, `stakeSelf` | 0010 | `staking` |
| K | Composition (`Compose`), `@Reads`, deposits (`@Receives`), migration (`@MigrateTo`/`@Migrate`) | 0011 | `oracle`, `fees`, `upgrade` |
| L | Several owned types, MerkleMaps in objects, moves between instances (`@Into`/`@Admits`) | 0012 | `guild` |
| M | CIP-30 wallets (`WalletAccount`, `Compose.prepare()`), contract descriptions, the JavaScript client, the prepare service, a browser dApp | 0013 | `wallet`, `dapp` |

See [Examples](/reference/examples/) for what each example shows and how to run it.

### JavaScript and npm (ADR-0015)

ADR-0015 ships JOUST to JavaScript developers as two prebuilt Wasm engines inside npm packages: a toolchain that
compiles `.jsc` and `.java` contracts in Node, and a runtime that prepares transactions in Node and in the browser.
Its milestones M0 to M4 are implemented; their evidence is recorded in ADR-0015 §13.

| Milestone | What it delivered |
|---|---|
| M0 | The runtime builds QuickTx `Tx` (never `ScriptTx`), and fixtures recorded on DevKit (`fixtures/m0`) became the oracle for everything after |
| S0 to S2b (gates) | The runtime in a Web Image; the toolchain engine compiling Counter, Bank and `.jsc` in Node; transition programs evaluated in the engine; read discovery for MerkleMaps |
| M1 | Description v2 with call recipes; one description-driven runtime core shared by the JVM and the engine; deterministic replay from a call request and a snapshot |
| M2 | The packages `@julclang/joust-runtime`, `@julclang/joust` and `create-joust`, beside `@julclang/state-client`; publishing to a local registry; the no-Java acceptance run |
| M3 | Feature parity through npm: every example's DevKit flow passes through the npm path, byte-identical to the JVM on the recorded fixtures (`fixtures/m3`) |
| M4 | `joust deploy` (preview through Blockfrost), `joust dev`, `joust serve`, the Vite plugin (`@julclang/joust/vite`), the engine in a page worker with SRI, pluggable chain providers (Blockfrost and Yaci Store, Ogmios), cardano-js-sdk instead of CSL, the Cardano Foundation's wallet connector, and MerkleMap mirrors |

M4's exit was a counter dApp on the preview testnet, made with `npm create joust` from the local registry,
prepared in the page's worker, verified by the page and signed by a browser wallet (ADR-0015 §13.11).

### Experimental

- **Option F** is a spike, not a product. ADR-0006 §3 lists what is not built: data availability at scale, deposits
  and exits, large states, liveness and censorship resistance, and generating the L2 program from a contract.
- **ADR-0013 phase 4** (a contract's Java compiled per contract with GraalVM Web Image, `-Ajoust.portable=true`)
  stays experimental. ADR-0015's engines replace it as the way to run contracts off chain.

## Known limits

- **Not through npm yet:** `@Votes` and `@Propose` calls (the JVM client has no calls for them either);
  `@Init`/`@OwnedInit` inside compositions; quorum and governors on owned objects; batches over maps or assets
  (ADR-0015 §13.8). No example needs them.
- **Batches** are memory-bound at about 8 intents (ADR-0004 §6).
- **Script size:** a transaction is at most 16 KB, so a script must stay well below it. Heavy contracts (three owned
  types with moves and maps) have exceeded it. See [Fees and script size](/contracts/fees-and-size/).
- **Mirrors over Ogmios alone** cannot be rebuilt from the chain: Ogmios serves no history, so it needs Kupo or an
  indexer beside it (ADR-0015 §13.12).
- **DevKit pays no rewards within a test** (rewards take epochs), so staking flows on DevKit collect a zero balance.

## What is next

### M5: the release pipeline

M5 is the last milestone of ADR-0015. Its scope, from the ADR's plan:

- **GraalVM images in CI.** Today the two Wasm engines are built locally, with a GraalVM install
  (`./gradlew npmPublishLocal -PgraalvmHome=...`); M5 builds them in JOUST's CI, from the same JuLC version the
  contracts compile against.
- **npm tarballs with provenance.**
- **Publishing to npmjs.org,** by maintainer decision (ADR-0015 Q4: the `@julclang` scope, provenance and the
  release-ops steps are decided before M5). Until then the local registry stands in, and the packages behave exactly
  as if published (ADR-0015 D9).

### Follow-ups found on preview

The maintainer's preview run with a real wallet (ADR-0015 §13.11) found two fee follow-ups:

- **Issue #33:** the fee overpays by one vkey witness (4,563 lovelace per call in that run).
- **Issue #34:** the reference-script fee was 29 % of a call's fee. Script size is now the largest part of a simple
  call's cost (ADR-0008).

### Upstream

- **JuLC.** JOUST needs JuLC's ADR-071 (`@OnchainLibrary` meta-annotations and a robust library-source scan,
  bloxbean/julc#311) and the embedder change of bloxbean/julc#313 (stacked on #311). Neither is published, so JOUST
  pins a locally built JuLC (`0.1.0-adr071-deb72bb-SNAPSHOT` in `gradle/libs.versions.toml`). When they are released,
  `build-julc.sh` and the snapshot workflow's `JULC_FROM_SOURCE` switch go away. JuLC's CIP-57 blueprint also lacks
  vocabulary for vote and propose handlers (hence `-Ajulc.blueprint=false`).
- **cardano-client-lib.** ADR-0001 §12 and ADR-0015 list: an option to keep an inline datum's map order instead of
  always writing canonical CBOR; documenting that QuickTx takes the fee from an output at the fee payer's address;
  duplicate keys in `MapPlutusData`; and keeping required signers in a stable order.

### Later

ADR-0015 §11 names work outside its scope: editor support (a `.jsc` language server), making `.jsc` the default
language for JavaScript developers, and a Kotlin front end (queued). ADR-0015 Q2 keeps open an export of a built call
as a CCL TxPlan, and JOUST as a QuickTx extension once CCL's prerequisites are met.

## How snapshots are published

The process is in [`docs/release-ops.md`](https://github.com/bloxbean/joust/blob/main/docs/release-ops.md).

| Piece | What it does |
|---|---|
| [`.github/workflows/build.yml`](https://github.com/bloxbean/joust/blob/main/.github/workflows/build.yml) | CI on pushes to `main` and `release/**` and on pull requests: builds JuLC from source, starts Yaci DevKit, runs `./gradlew build` (JVM, harness and DevKit tests, the JavaScript client's tests) and checks the publication scope |
| [`.github/workflows/bloxbean-snapshot.yml`](https://github.com/bloxbean/joust/blob/main/.github/workflows/bloxbean-snapshot.yml) | Manual. Publishes a commit of `main` or `release/**` whose `build.yml` run passed, to `https://repo.bloxbean.org/maven/snapshots`, and updates the [Development snapshot](https://github.com/bloxbean/joust/releases/tag/snapshot) pre-release |
| `build.gradle` | Snapshot versions carry the commit: `0.1.0-pre1-SNAPSHOT` becomes `0.1.0-pre1-<sha7>-SNAPSHOT`. Six library modules publish a jar, sources, javadoc and POM; `julc-state-api` adds its `onchain` jar for consumers' annotation processor path |
| `.github/ci/build-julc.sh` | Builds the pinned JuLC into mavenLocal, as CI does (temporary, until JuLC is published) |

The published modules are `julc-state-api`, `julc-state-dsl`, `julc-state-processor`, `julc-state-runtime`,
`julc-state-testkit` and `julc-state-verifier`. The snapshots are read anonymously, but their POMs name the locally
built JuLC, so a consumer runs `build-julc.sh` first (see [Quick start: Java & Gradle](/start/quick-start-java/)).

The npm packages are versioned `0.1.0-pre1-snapshot` and published only to a local registry for now:
`./gradlew npmPublishLocal -PgraalvmHome=...` builds both engines and runs `js/publish-local.sh`, and
`./gradlew npmAcceptance -PgraalvmHome=...` runs the npm-only developer flow on DevKit in a shell where no Java can be
found.

Install JOUST

Everything starts from one command, joust. It creates a project for the path you choose, and inside a project it runs that project’s build. This page installs it, with the few tools your path needs, and shows how to check which JOUST version you are on.

Experimental, pre-release

JOUST is a research and learning project: do not use it in production. Releases come often. The newest one is the newest entry on the releases page whose tag starts with v (not the “Development snapshot” entry). Check there before you start, and when something you read here does not match what you see.

Install

Section titled “Install”

  1. Install joust.

    • Homebrew
    • Release archive
    • npm only (experimental)

    For Apple silicon Macs and Linux (x86_64, arm64). There is no native joust for Intel Macs or Windows. There, a Java project needs its build written by hand (Gradle builds), and a JavaScript project uses the npm path.

    Download joust-<version>-<platform>.zip and joust-<version>-SHA256SUMS.txt for your platform (<platform> is macos-aarch64, linux-x86_64 or linux-arm64) from the newest release on the releases page. Check it, unpack it and put joust on your PATH:

    On macOS, also clear the quarantine flag, since the binary is not notarised: xattr -d com.apple.quarantine joust.

    On the npm path you do not need the native joust: npm create joust@latest creates a project, and the project’s own @julclang/joust gives you npx joust and the npm run scripts. See Quick start: JavaScript & TypeScript.

    Do not also install @julclang/joust globally next to the native joust: both install a command named joust, and the second would replace the first. Keep the native one global and @julclang/joust per project.

    The native joust is a single binary: it needs neither a JDK nor Node to run.

  2. Check it.

    On the npm path you check the version later, inside your project after npm install, with npx joust version (Quick start: JavaScript). Outside a project, npx joust would fetch an unrelated package.

    Compare <version> with the newest release on the releases page. joust new writes the version of the joust that runs it into the project, so upgrade before you create a project (brew upgrade joust, or a newer archive).

  3. Install what your path needs.

    • Gradle (Java or .jsc): JDK 25. You do not need Gradle: joust new writes the Gradle wrapper (./gradlew) into the project.
    • npm (JavaScript, experimental): Node 22 or newer. The playground (joust playground) needs Node 22 too, on both paths.

  4. Install and start a local Cardano network. The quick starts run on Yaci DevKit, a private Cardano network on your machine: its faucet hands out test ADA, so nothing costs real money. Install it once (it needs Node.js; DevKit’s README also has Docker and zip distributions, which start differently):

    Start it with its indexer, Yaci Store, in a terminal of its own, and leave it running (the first start downloads what it needs, so it takes longer):

    You only need DevKit for the steps that run on a chain: building, the tests and the playground work without it.

    Yaci Store then answers on http://localhost:8080 (a Blockfrost-compatible API), the DevKit admin API on http://localhost:10000 (slot clock, faucet), and the Yaci Viewer explorer on http://localhost:5173. See Networks and chain providers.

Which JOUST version a project uses

Section titled “Which JOUST version a project uses”

A project pins its JOUST version in one place. Upgrading JOUST means changing that version, after checking the releases page for the newest one.

  • Java
  • .jsc
  • JavaScript

The Gradle plugin brings every other version (JuLC, cardano-client-lib) from the JOUST release it belongs to, so they always match. See Gradle builds.

The same build.gradle line as for Java: a .jsc project on Gradle is a Java project with its contract in src/main/jsc/.

All three are released together, at the same version. npx joust version prints the one the project uses, and npm view @julclang/joust version the newest on npm.
